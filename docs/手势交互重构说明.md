# 手势交互重构说明

本版将手势输入统一映射为与鼠标相同的“指向、按下、持续移动、释放”语义。地图、知识星图和工艺模型只负责处理各自的 Three.js 视角，不再分别判断手势状态。

## 操作映射

- 食指移动：移动虚拟指针并触发悬停。
- 捏合后立即松开：点击按下时锁定的目标；屏幕空间容差会吸收摄像头放大后的自然手抖。
- 捏合保持约 520ms：取得按下时 Three.js 场景的独占操作权；随后移动才会旋转，左右改变水平旋转，上下改变俯仰。
- 张掌按住并移动：直接拖动当前场景，释放后结束拖拽。
- 拖动过程中离开原节点：仍作用于按下时的 Three.js 场景，不会丢失地图旋转。
- 非遗图片、模态框、智能体面板和普通 DOM 控件独占自己的按下会话，不会穿透旋转后面的场景。

## 命中与所有权

- 精确 DOM 命中以浏览器实际最上层元素为准，不再按全页控件面积猜测目标。
- 没有精确 DOM 目标时才启用按钮扩展命中区，之后才进入 Three.js 射线检测。
- 地图射线提供小范围屏幕空间容错，用于薄区块边缘；精确射线始终优先。
- 按下时锁定目标。短按、长按和拖拽共享同一会话，任何阶段都不会把 DOM 操作兜底给背景地图。
- 手势状态组件可独立挂载到 `document.body`；初始化失败会输出明确警告，不再被静默吞掉。

## 验证

```bash
npm.cmd run gesture:test
npm.cmd run map:test-ui
npm.cmd run graph:test-ui
npm.cmd run mascot:test-ui
```

`gesture:test` 验证自然抖动点击、长按前禁止旋转、长按后拖拽与统一释放；`map:test-ui` 在真实浏览器中验证手势系统初始化、非遗图片命中并打开详情、地图长按旋转；`graph:test-ui` 覆盖地图射线、知识星图和工艺模型；`mascot:test-ui` 回归小猫拖动与释放。

控制器提供 `controller.simulate(event)` 作为诊断入口。它只用于自动化测试或开发调试，生产环境仍由摄像头和 MediaPipe 产生同样的事件。
