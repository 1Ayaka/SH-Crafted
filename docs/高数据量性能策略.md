# 高数据量性能策略

本轮性能迭代针对智能体面板、图谱检索和服务端内容读取三个热点。

## 已实施

- 智能体侧栏使用独立合成层覆盖显示，不再修改 `#app` 的宽度或内边距，避免地图、星图和模型画布重新布局。
- 语音控制器和工具注册表改为首次使用时初始化，单纯打开面板不会启动语音相关逻辑。
- 页面上下文使用有限字段签名判断变化，不再对完整上下文反复 `JSON.stringify`。
- 图谱节点、边、ID 映射和搜索字段按内容版本建立一次索引；重复搜索不重新拼装全部节点。
- 搜索使用二字词和英文词索引先缩小候选集，再进行相关度评分。
- 服务端把管理员内容片段按 revision 缓存并按项目预分组，问答时不再重复扫描全部项目和工序。
- `/api/content` 按 revision 缓存序列化结果并支持 ETag/304，多个访客不会反复消耗服务器 CPU 序列化相同大对象。
- 长对话中的历史消息使用 `content-visibility: auto`，屏幕外消息跳过布局和绘制。

## 当前基线

- `/api/content`：约 188 KB。
- 智能体面板首帧唤起：约 75 ms，主应用右内边距保持 0，不触发 WebGL resize。
- 178 个运行时图谱节点下连续检索 3000 次：平均约 0.03 ms/次，索引构建 1 次。

运行回归：

```bash
npm.cmd run performance:test
npm.cmd run agent:test-tools
npm.cmd run graph:test-ui
npm.cmd run ui:test
```

## 数据增长阈值

- `/api/content` 超过 1 MB：把项目详情和工序拆为按项目请求，首屏只保留目录、计数和概览图。
- 图谱节点超过 5000：将布局放入 Web Worker，并保持当前两级按需展开。
- 单次会话超过 100 条消息：只保留最近消息 DOM，较早消息序列化到会话记录并按需恢复。
- 图片超过 500 张：使用缩略图、懒加载、固定尺寸和对象存储 CDN，不把大图 Data URL 写入主内容响应。
- 知识片段超过 10000：把当前内存扫描替换为 SQLite FTS5 或独立向量检索，并保留来源与审核状态过滤。

这些阈值是发布监控线，不应等到用户感到卡顿后才拆分。
