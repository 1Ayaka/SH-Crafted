# 手势交互部署与使用

手势功能是 SH-Crafted 的增强输入方式，不能替代鼠标、键盘、触屏或文字/语音操作。未点击“开启手势”并完成浏览器授权前，页面不会访问摄像头。

## 当前能力

手势输入共用现有页面操作链：

- 页面实时绘制 MediaPipe 21 点镜像虚拟手：玉石白骨架、苔绿色关节点，并在手掌旁显示当前识别动作。不需要额外下载或提供三维手模型。
- 食指移动：移动虚拟手与隔空指针，命中地图、星图、完成品模型和 DOM 控件。
- 拇指与食指捏合后松开：等价于鼠标点击。系统使用二维指尖距离避免深度估计抖动，并在捏合开始时锁定目标，松开时不会因手指位移误点到相邻目标。捏合期间指针锁定在起始位置，只跟随手根部稳定锚点的位移，指尖卷曲不会带动指针。
- 张掌并稳定约 5 帧：直接进入鼠标按下状态；之后每一帧掌心位移都会驱动地图、星图或模型旋转，不再等待点击/长按的移动阈值。食指与中指伸直即可判定，四指中允许一根（通常是小指）识别抖动；拇指放松搭在食指附近不会压制张掌。收掌连续约 4 帧后释放，短暂识别抖动不会中断拖拽。
- 持续捏合约 560ms：进入长按；捏合后移动超过屏幕像素阈值时立即进入拖拽。未进入拖拽时松开才触发点击，拖拽结束不会误点。
- 握拳并稳定约 5 帧：缩小当前地图、模型或星图；持续握拳时每约 650ms 克制地重复缩小一次，松拳立即停止。
- 指针位于阅读面板顶部或底部热区：等价于鼠标滚轮滚动。
- 从右向左挥手：为避免抢占张掌横向拖拽，默认关闭；如项目方确实需要，可通过 `swipeEnabled` 单独开启。

Three.js、DOM 和手势动作均经过 `target-resolver` 与 `action-registry`，手势模块不直接拼接路由，也不直接改写页面业务状态。

食指位置同时驱动统一的虚拟鼠标事件桥。页面会收到与鼠标对应的 `pointerenter`、`pointermove`、`pointerleave`、`pointerdown`、`pointerup` 及兼容 MouseEvent。捏合负责点击与长按；张掌使用独立的直接拖拽会话，锁定按下时的 Three.js 场景并持续调用该场景原有的旋转适配器。地图区块升起、星图节点悬停、DOM 按钮反馈仍共用原来的鼠标处理逻辑。

点击与拖拽采用“指向—确认—操纵”三段式：食指尖负责瞄准和锁定目标；捏合走点击/长按状态机，拖拽阈值约 10–12 CSS 像素，按下时的目标解析以用户实际看到的平滑指针位置为准；张掌则明确表示“鼠标左键已按下”，使用掌心稳定锚点直接输出拖拽增量，不经过点击阈值。完成品与全屏星图不会同时持有活动拖拽上下文，关闭星图后会恢复完成品模型上下文。

按钮和链接默认增加约 30 CSS 像素的手势命中扩展区。扩展区只作用于手势解析，不改变按钮视觉尺寸、鼠标真实命中范围或键盘焦点顺序；如果两个按钮扩展区重叠，优先选择距离指针最近的按钮。

坐标映射默认使用横向和纵向 10% 的摄像头安全区：安全区内靠近边缘的手部位置会映射到屏幕边缘，手不需要抵到摄像头画面的最外侧。中心位置仍保持约 1:1 映射，避免页面中部操作过度敏感。

松开捏合后页面会显示“已点击：目标名称”或“当前位置没有可点击目标”。最近一次执行结果同时写入只读诊断对象 `window.__gestureLastAction`，包含是否执行、命中层、场景和目标，不包含摄像头画面或个人信息。地图页会监听全局手势就绪事件并以 250ms 间隔补注册，消除地图与异步手势模块加载顺序不同造成的点击丢失。

## 浏览器与服务器要求

生产环境必须使用 HTTPS；本地开发可使用 `http://localhost`。通过公网 IP 的普通 HTTP 访问不能申请摄像头权限。推荐使用最新版 Chrome 或 Edge 桌面版，并启用 WebGL、Web Worker 和 `createImageBitmap`。

Firefox、Safari 或不支持摄像头/Worker 的环境仍可正常浏览网站，但手势按钮会提示不可用，鼠标、键盘和语音入口不受影响。

模型资源随仓库提供，不需要浏览器访问第三方 CDN：

```text
vendor/mediapipe/hand_landmarker.task
vendor/mediapipe/vision_bundle.mjs
vendor/mediapipe/vision_wasm_internal.js
vendor/mediapipe/vision_wasm_internal.wasm
```

这些文件必须和站点保持同源可访问。部署后先检查：

```bash
curl -I https://你的域名/vendor/mediapipe/hand_landmarker.task
curl -I https://你的域名/vendor/mediapipe/vision_bundle.mjs
```

返回 `200` 后再在浏览器中开启手势。

## 直接部署

服务器上使用与现有站点相同的 Node + systemd + Nginx 方案：

```bash
cd /var/www/sh-crafted
git pull --ff-only origin main
npm ci --omit=dev --ignore-scripts
npm run check
npm run gesture:test
sudo systemctl restart sh-crafted
sudo systemctl is-active sh-crafted
```

Node 仍监听 `127.0.0.1:7100`，Nginx 对外提供 HTTPS。现有模板 `deploy/nginx.conf.example` 已经包含 `/js/`、`/vendor/` 和 `/data/` 的静态文件代理规则，不需要为手势单独增加端口。

首次配置或服务器没有现成站点时，按 [`DEPLOYMENT.md`](../DEPLOYMENT.md) 完成：

1. 安装 Node.js 22 或更高版本、Nginx 和 systemd。
2. 部署仓库并执行 `npm ci --omit=dev --ignore-scripts`。
3. 安装 `deploy/sh-crafted.service`。
4. 安装 `deploy/nginx.conf.example` 并执行 `nginx -t`。
5. 使用 Certbot 配置 HTTPS。
6. 通过 `curl -I` 检查首页和 MediaPipe 资源。

## 用户首次使用

1. 打开 HTTPS 站点。
2. 点击右下角“手势”。
3. 阅读本地处理与摄像头用途说明，点击“开启手势”。
4. 在浏览器权限提示中允许摄像头。
5. 等待“手势就绪”或“手势跟踪中”。
6. 将整只手放在摄像头画面中央；检测成功后页面会出现虚拟手骨架和当前动作标签。
7. 伸出食指移动；张掌按住后移动旋转，收掌释放；捏合用于点击或长按；握拳缩小。

用户可以在设置中调整指针灵敏度、指针速度、捏合触发距离和下次是否自动启用。页面进入后台时会显示“手势已暂停”，回到页面后自动恢复；如果浏览器或设备中断了摄像头，可以关闭后重新开启。

## 故障排查

### 显示“当前页面未使用 HTTPS”

使用 HTTPS 域名，或本机使用 `http://localhost:7100`。不要用服务器公网 IP 的普通 HTTP 访问。

### 显示“摄像头权限未开启”

点击地址栏摄像头图标，允许当前域名使用摄像头，然后关闭并重新开启手势。浏览器拒绝权限后不会循环弹窗。

### 模型加载失败

检查四个 MediaPipe 文件是否存在、是否返回 `200`，并检查 Nginx 是否把 `.wasm` 和 `.task` 作为静态文件返回。浏览器开发者工具 Network 中不应出现 `404` 或跨域错误。

### 手势暂时不可用

继续使用鼠标或键盘，不会影响地图、三维模型和知识图谱。可检查设备是否被其他视频会议软件占用，或刷新页面后再次授权。

### 张掌无法旋转地图或模型

按顺序检查：

1. 语音助手正在聆听或说话时会暂时抑制张掌按下，等播报结束后再试。
2. 食指和中指需要明显伸直；小指或无名指轻微弯曲不影响判定。
3. 指针应停在三维画布内再张掌；指针落在按钮或面板上时，张掌会作用于该控件而不是场景。
4. 摄像头帧率过低时 5 帧稳定窗口会更长，可保持手型稳定约半秒。

## 开发验证

```bash
npm run check
npm run gesture:test
```

`gesture:test` 覆盖扁平/对象两种关键点格式、原始捏合生命周期、屏幕像素点击/拖拽/长按状态机、长按转拖拽、稳定操纵锚点、拳/掌识别、动作注册和 Three.js 动态目标解析。`graph:test-ui` 额外检查独立星图、键盘节点入口、Logo 路由、材质、悬停与资源销毁。摄像头真实识别仍需在 HTTPS 浏览器中手动验证：虚拟手显示、左右镜像、食指命中、捏合点击、长按、拖拽旋转、拳/掌缩放、防重复触发、左挥返回、隐藏页面恢复和关闭后再次开启。

`graph:test-ui` 还会在无头 Edge 中真实加载本地 MediaPipe Worker、WASM 和手部模型。Worker 会先尝试 GPU；虚拟机、关闭硬件加速或 GPU 初始化失败时自动回退 CPU。模型初始化期间不得覆盖 Worker 的常驻消息处理器，否则会出现摄像头短暂开启但不再接收画面帧的问题。

### 可调参数

- `pinchStartRatio` / `pinchReleaseRatio`：捏合进入与释放迟滞阈值。
- `pinchStableFrames`：捏合开始和释放的稳定帧数，当前为 2 帧。
- `clickCooldownMs`：连续点击冷却，默认灵敏度下约为 190ms。
- `palmPressStableFrames` / `palmReleaseStableFrames`：张掌按下和释放所需的稳定帧数，当前为 5 帧和 4 帧。
- `palmDragSmoothing` / `palmDragGain` / `palmDragMaxDeltaPx`：张掌直接拖拽的平滑、移动增益与单帧异常位移上限，当前为 0.58、1.15 和 64px。
- `longPressMs`：捏合长按时间，当前为 560ms。
- `dragThresholdPx`：按住后进入拖拽的屏幕距离，随灵敏度在 10–12 CSS 像素间调整，默认约 11px。
- `stationarySlopPx`：长按静止窗口允许的平滑位移，当前为 8px。
- `dragSmoothing`：操纵锚点逐帧平滑系数，当前为 0.30。
- `pinchSmoothing` / `pinchSmoothingClose` / `pinchReleaseFrames`：捏合距离 EMA 系数（张开方向）、闭合方向 EMA 系数和释放连续帧数，当前为 0.35、0.55 和 3 帧。闭合方向系数更大，让捏合尽快得到确认。
- `hitSlopPx`：标准按钮和链接的手势扩展命中区，默认约 30 CSS 像素。
- `edgeInsetX` / `edgeInsetY`：摄像头安全区映射，默认横纵向均为 0.10；提高后更容易触达页面边缘，但中心区域会更敏感。
- `fistStableFrames` / `fistRepeatMs`：握拳稳定帧数与持续缩小间隔，当前为 5 帧和 650ms。
- `swipeEnabled`：是否启用张掌左挥返回，默认关闭，避免与地图和模型横向旋转冲突。
- 上述参数应依据服务器测试机摄像头帧率和真实用户评测再调整。

### 交互设计依据

本实现参考成熟空间交互中的共同原则，并结合普通 RGB 摄像头的误差做了工程化取舍：

- [Apple visionOS：空间交互](https://developer.apple.com/visionos/get-started/) 将间接捏合作为选择手势，并将轻点、拖拽、长按、缩放和旋转定义为可组合的标准动作。
- [Microsoft：Point and commit](https://learn.microsoft.com/en-ca/windows/mixed-reality/design/point-and-commit) 使用“先指向目标、再捏合确认”，捏合保持并移动用于拖动。
- [Ultraleap：Far Field Ray](https://docs.ultraleap.com/ultralab/far-field-ray-blog.html) 指出捏合会带来瞄准抖动，建议对射线进行稳定化处理；本项目据此将视觉指尖与拖拽操纵锚点分离。
- [Ultraleap：Hand Poses](https://docs.ultraleap.com/xr-guidelines/Interactions/hand_poses.html) 强调手势识别过程必须提供清晰、持续的视觉反馈。
- [MediaPipe Hand Landmarker](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/HandLandmarkerOptions) 提供视频/实时模式及检测、跟踪置信度配置；本项目在其 21 点结果之上独立实现输入状态机，不把识别分类器直接等同于鼠标事件。

## 回滚

手势资源和脚本随同一版本发布。若线上手势异常，先回滚整个应用版本，不要只删除某一个模型文件：

```bash
cd /var/www/sh-crafted
git log --oneline -5
git checkout --detach 上一个稳定提交
npm ci --omit=dev --ignore-scripts
npm run check
sudo systemctl restart sh-crafted
```

回滚不会影响管理员内容存储目录 `/var/lib/sh-crafted`。完成后恢复部署分支，并按现有发布流程重新部署。
