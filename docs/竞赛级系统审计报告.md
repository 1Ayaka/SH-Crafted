# 探物志竞赛级系统审计报告

审计目标：以国家级智能体应用竞赛最高奖项为标准，从访客、内容审核管理员、代码维护者三种角色检查系统闭环。

## 审计范围与实测结果

### 访客角色

- 地图、地区聚焦、非遗详情、工艺工作台、知识星图可以进入。
- 智能体工具测试通过，知识库 API 对 8 个主项目均可返回命中结果。
- 手势测试通过：地图、星图、模型的拖动和点击使用同一套虚拟指针语义。
- 社区投稿接口通过：投稿进入待审核状态，不会直接出现在正式内容中。

### 内容审核管理员角色

- 管理员登录、项目编辑、工序编辑、材料流转、纪录片片段字段、知识星图编辑和社区投稿审核均有自动化覆盖。
- 内容审核状态使用 revision 乐观锁；旧页面保存时会收到冲突，不会静默覆盖新版本。
- 管理员导入要求至少一张带说明的概览图，导入内容会追加为新项目，不会覆盖同 ID 的已有项目。

### 代码维护者角色

- 正式内容已经迁移到 SQLite；代码部署目录与内容数据库分离。
- 数据库保留历史版本，部署脚本使用 fast-forward 更新并执行语法检查。
- 已提供备份、图谱补丁预览/应用和知识库审计工具。

当前数据规模基线：8 个主项目、38 道工序、24 张工序图、187 个图谱节点、83 条图谱边、850 个知识库片段、44 个来源、85 条外部事实，其中 83 条已外部核验。

## 优先级建议

### P0：上线前必须完成

1. **禁止生产环境使用默认管理员密码。** 当前代码在未配置环境变量时仍回退到 `djt / 12345689`。生产启动应要求显式设置 `ADMIN_PASSWORD`，并在部署检查中拒绝默认值；测试环境通过 `ADMIN_SMOKE_USERNAME` 和 `ADMIN_SMOKE_PASSWORD` 注入。
2. **把 FunASR 健康状态纳入发布门禁。** 当前语音 API 冒烟能成功签发会话，但本机测试显示 FunASR provider 为 `down`。线上发布必须同时检查 `/api/voice/health`、WebSocket 建连和至少一段真实 PCM 音频，否则只能声明“语音降级可用”。
3. **建立公开演示的故障降级路径。** DeepSeek、FunASR、图片和模型任一外部资源失败时，界面应保持可探索，并显示非阻塞状态；错误不能弹出到对话框或打断当前流程。

### P1：直接影响评委体验

1. **设计一条 3 分钟演示剧本并固定入口。** 从首页荷叶互动进入地图总览，输入“竹子”触发智能体关联，进入一个项目，完成一道工序，再从节点进入星图。每一步都应有可见反馈、返回路径和当前上下文。
2. **为智能体增加可验证评测集。** 至少覆盖材料探索、地域原因、当前页面理解、工序解释、纪录片讲解、星图跳转和无资料回答。记录工具调用、引用来源、响应时间、是否输出内部 ID/审核标记，并在 CI 中回归。
3. **统一内容状态展示。** 用户端不应出现内部 `needs_review`、事实 ID 或异常代码；审核员需要在后台看到来源、审核人、时间和变更差异，而不是只看到一个全局勾选框。
4. **修复完整 UI 烟测中的已知失败项。** 当前 `ui:test` 在 CPU 环境曾报告地图水面残留、无项目行政区无法真实进入、地区面板动画缺失和聚焦后空白返回异常。它们不一定阻断核心功能，但会直接影响现场演示的完成度。

### P2：扩展性与长期维护

1. **图谱采用视口级别的渐进加载。** 首屏只加载主节点和一级关系；点击节点后再请求两级分支，超过视口或节点数阈值时使用 Web Worker 布局，避免数据增长后主线程卡顿。
2. **为内容导入增加预览、差异和回滚。** 管理员导入前显示新增/修改/冲突数量；应用后可按导入批次回滚。图谱补丁已有该方向，项目内容导入也应复用同一套机制。
3. **为图片、视频和模型建立资源清单。** 每项资源记录版权来源、许可状态、尺寸、校验哈希和失效检查结果，发布前运行链接检查，避免现场出现空白媒体。
4. **补齐可访问性和移动端验收。** 键盘节点入口、焦点样式、ARIA 标签、减少动画和低带宽模式应纳入发布清单；手势不可用时鼠标、触摸和键盘必须完成同样流程。

## 推荐发布门禁

```text
代码检查 -> 单元测试 -> 管理员/社区/知识库 API 烟测
-> 浏览器用户流程 -> 智能体评测集 -> FunASR 实链路
-> 内容数据库备份 -> 版本与数据库 revision 记录 -> 发布
```

发布前至少执行：

```bash
npm.cmd run check
npm.cmd run gesture:test
npm.cmd run graph:test
npm.cmd run graph:test-ui
npm.cmd run admin:test-ui
npm.cmd run community:test
npm.cmd run kb:test-api
npm.cmd run kb:audit
npm.cmd run voice:test-api
npm.cmd run audit:production-config
```

`audit:production-config` 在 `NODE_ENV=production` 时会拒绝默认管理员密码、未启用安全 Cookie 或未配置独立内容数据库路径；本地开发模式不受影响。

本报告不是“已获得最高奖项”的承诺；它标出了当前系统的真实证据、上线阻断项和下一轮最值得投入的工作顺序。
