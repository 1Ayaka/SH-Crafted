# 探物志 知识库建设与维护手册

## 1. 目标与边界

知识库为地图介绍、项目详情、数据护照和“小蕉”问答提供可追溯资料。它同时保存两类内容：

1. 比赛视频衍生数据：转写、关键帧、事实主张、候选工序与实体。此类内容默认 `needs_review`，必须保留时间码或证据编号。
2. 外部资料：国家级非遗名录、政府部门、公共文化机构和官方文旅平台。网页只使用摘要性转述，不复制整篇原文；每条事实必须保存来源编号、原文链接、权威等级和审核状态。

知识库不把百科、自媒体、电商页面和无署名转载作为独立事实依据。它们可以用于发现线索，但线索必须回到 A/B 级来源核验。

## 2. 来源分级

| 等级 | 可接受来源 | 使用方式 |
| --- | --- | --- |
| A | 国家与省市政府、国家级非遗名录、国家级博物馆、正式政策文件 | 可支持名录、年代、项目类别、保护单位等核心事实 |
| B | 上海市/区级政府、文化主管部门、公共文化机构 | 可支持地方历史、活动、保护实践和传承情况 |
| C | 政府指导的官方文旅平台、国有文化机构或权威媒体转载 | 用于补充展示、传播和参观信息，重要事实应与 A/B 级交叉核验 |

来源网页发生变化时，不直接覆盖旧结论。先重新抓取，对比快照，再决定修改事实、保留历史版本或建立冲突记录。

## 3. 目录与数据流

```text
sources.json ──登记来源与抓取策略──┐
                                    ├─ kb:build ─ index.jsonl / stats.json
facts.jsonl ──可引用外部事实────────┤                    │
                                    │                    ├─ /api/kb/search
data/SHIH_*/knowledge/* ──视频资料──┘                    └─ /api/agent → 小蕉

sources.json ── kb:crawl ─ snapshots/*.json / crawl-report.json
                                  │
                                  └─ kb:audit 校验链接、哈希、覆盖与引用
```

核心文件：

- `data/knowledge-base/sources.json`：来源登记册与权威策略。
- `data/knowledge-base/facts.jsonl`：经过转述的外部事实。
- `data/knowledge-base/index.jsonl`：自动生成的统一索引，不手工编辑。
- `data/knowledge-base/stats.json`：索引规模、类型和项目覆盖统计。
- `data/knowledge-base/snapshots/`：网页抽取快照，仅供核对。
- `data/knowledge-base/audit-report.json`：最后一次质量审计结果。

## 4. 新增资料的标准流程

1. 在 `sources.json` 登记唯一 `source_id`、标题、发布机构、HTTPS 链接、等级、主题、相关项目和抓取格式。
2. 对 HTML 来源运行 `npm run kb:crawl -- --source=<source_id>`，检查抓取状态、正文长度与主题命中。
3. 阅读权威原文，以自己的语言将可核验事实写入 `facts.jsonl`。一条事实只表达一个主要结论，并填写 `source_ids`、`authority_tier`、`review_status` 和 `evidence_locator`。
4. 依次执行构建与审计：

   ```bash
   npm run kb:build
   npm run kb:links
   npm run kb:audit
   ```

5. 启动网页后执行接口回归：

   ```bash
   npm run dev
   npm run kb:test-api -- --base=http://127.0.0.1:7100
   ```

6. 打开“数据护照”，确认片段、事实、来源和项目覆盖统计同步更新；再在具体工艺页向“小蕉”询问新增主题，核对回答中的来源链接和审核标签。

## 5. 事实写作与审核规则

- 原文中的明确事实采用摘要性转述；不保存长段复制内容到面向用户的事实库。
- 项目名称、级别、类别、编号、批次、保护单位和代表性传承人属于高风险字段，优先用正式名录核验。
- 地方传说、口述历史与作品评价应写明“资料记载”“地方传说”或“报道介绍”，不得改写成考古或学术定论。
- `verified_external` 表示该条摘要与所列外部来源一致，不代表比赛方已经完成人工终审。
- 视频自动抽取数据维持 `needs_review`，人工审核后才可更新状态，并记录审核人和时间。
- 不删除相互冲突但来源可靠的记录；分别保存，并增加冲突说明等待人工判断。

## 6. 发布前质量门槛

- 每个已上线项目至少 10 条外部事实、5 个独立来源、6 类事实主题，且至少有一个 A/B 级来源。
- 所有事实编号、来源编号和索引编号唯一；不存在悬空引用。
- 所有启用抓取的 HTML 来源有成功抓取记录，快照 SHA-256 与报告一致。
- `npm run kb:links`、`npm run kb:audit`、`npm run kb:test-api` 和 `npm run check` 全部通过。
- 数据护照统计与 `stats.json` 一致；问答结果不会跨项目混入其他项目的专属资料。

## 7. 服务器更新

知识索引在 `server.mjs` 启动时载入内存。因此 Git 拉取并运行 `npm run kb:build` 后，需要重启 `sh-crafted.service` 才会让新索引进入检索：

```bash
cd /var/www/sh-crafted
git pull --ff-only
npm run kb:build
npm run kb:audit
sudo systemctl restart sh-crafted
sudo systemctl reload nginx
```

重启后可在服务器执行：

```bash
npm run kb:test-api -- --base=http://127.0.0.1:7100
```

任何密钥只能放在服务器 `.env` 或系统环境变量中，不得写入知识库、截图、Git 提交或浏览器代码。
