# 小猫智能体吉祥物制作与接入方案

## 目标

小猫是“探物志”的探索伙伴，不只是聊天头像。它需要让用户一眼分辨智能体正在待机、聆听、思考还是回答，并支持鼠标、触摸与摄像头手势将它拎起。被拎起时身体跟随抓取点，四肢、脚掌和尾巴通过网页实时物理自然摆动。

第一版采用免费工作流：Krita 或 Inkscape 绘制分层素材，网页使用 PixiJS 渲染、Matter.js 计算关节和弹簧。动画不依赖 Rive、Spine 等付费编辑器导出。

## 绘制规格

- 原稿画布：1024 × 1024 px，透明背景，sRGB。
- 所有部件使用同一画布尺寸和同一原点，不要裁切为各自最小边界。
- 小猫静止姿态占画布中央约 70%，耳朵和尾巴最远动作不超过 88% 安全区。
- 关节连接处多画 20–40 px 的遮挡余量，旋转后不能露出空白。
- 正常显示尺寸约 160–280 px，因此最细线条在原稿中不低于 8 px。
- 主体保持现有绿色，橙色只用于可交互提示、发现线索和抓取反馈。

├─ front-paw-right
├─ back-leg-left-upper
├─ back-leg-left-lower
├─ back-paw-left
├─ back-leg-right-upper
├─ back-leg-right-lower

## 抓取点与关节标注

另建一个不导出的 `rig-guide` 图层，标出：

- 后颈抓取点：用户实际拎起小猫的位置。
- 头颈、肩、肘、腕、髋、膝、踝和三段尾巴关节中心。
- 每个部件的默认旋转中心。
- 身体重心与落地基线。

程序会为关节设置角度限制，避免腿反向翻转。前腿质量较轻、响应较快；后腿略重；尾巴阻尼最低，形成逐段延迟。静止后应在约 1–1.5 秒内稳定。

### `rig-guide` 实际制作方法

`rig-guide` 不是要导出的角色部件，也不需要画成真正的骨骼。它是一张与原稿完全重合的定位覆盖图，开发时用它读取关节坐标。

1. 保持原稿为 `1024 × 1024 px`，先打开所有正常姿态图层，让完整小猫可见。
2. 在最上方新建图层组并命名为 `rig-guide`，混合模式使用“正常”，不透明度可临时设为 70%。
3. 开启像素标尺和坐标显示；所有坐标都从画布左上角 `(0, 0)` 开始记录，不从小猫身体边缘计算。
4. 用橙色实心圆标出唯一抓取点 `grab-neck`。建议放在后颈皮肤范围内，不要放在头顶或耳朵上。
5. 用红色实心圆标出所有旋转中心。圆直径建议 16–20 px，并在旁边写英文 ID。
6. 用蓝色直线连接父节点和子节点，只表示结构关系，不需要沿着腿部曲线绘制。
7. 用青色十字标出 `body-center`，用一条紫色水平线标出 `ground-line`。
8. 隐藏角色图层检查一次，确保所有点、标签和连线都清楚；再重新显示角色，确认关节点确实位于部件重叠区域。

推荐颜色仅用于开发识别：

| 标记 | 颜色 | 含义 |
|---|---|---|
| 橙色圆 | `#F28C28` | 后颈抓取点 |
| 红色圆 | `#E53935` | 旋转关节/部件 Pivot |
| 蓝色线 | `#2684FF` | 父子连接关系 |
| 青色十字 | `#00A6A6` | 身体重心 |
| 紫色横线 | `#8E44AD` | 默认落地基线 |

### 点位命名与连接顺序

```text
body-center
├─ neck → head
│  ├─ ear-left
│  └─ ear-right
├─ shoulder-left → elbow-left → wrist-left → front-paw-left
├─ shoulder-right → elbow-right → wrist-right → front-paw-right
├─ hip-left → knee-left → ankle-left → back-paw-left
├─ hip-right → knee-right → ankle-right → back-paw-right
└─ tail-root → tail-joint-01 → tail-joint-02 → tail-tip
```

肩、髋和尾根点画在身体图层内部；肘、膝画在上下肢的重叠中心；腕、踝画在脚掌与小腿的重叠中心。耳朵只需要各一个根部 Pivot。点不要画在外轮廓边缘，否则旋转后容易露缝。

另外保留一张坐标表，文件名为 `rig-guide.csv`：

```csv
id,x,y,parent
grab-neck,512,250,body-center
body-center,512,520,
neck,512,345,body-center
shoulder-left,410,430,body-center
elbow-left,370,555,shoulder-left
wrist-left,360,675,elbow-left
```

上面的数字只是格式示例，必须替换成你画面中的真实像素坐标。左右命名以“小猫自身的左、右”为准，不以观看者视角为准。最终同时交付可编辑原稿、完整合成预览、`rig-guide.png` 和 `rig-guide.csv`。

## 第一版状态

| 状态 | 画面表现 | 是否循环 |
|---|---|---|
| 待机 | 轻微呼吸、眨眼、尾巴慢摆 | 是 |
| 唤醒 | 耳朵抬起，目光转向用户 | 否 |
| 聆听 | 目光跟随输入点，耳朵随音量轻动 | 是 |
| 思考 | 视线在两侧移动，橙色线索点依次亮起 | 是 |
| 回答 | 嘴部小幅切换，身体保持稳定 | 是 |
| 发现线索 | 一只前爪指向站内链接或当前页面内容 | 否 |
| 被拎起 | 表情响应抓取，四肢和尾巴由物理系统控制 | 持续 |
| 松开落地 | 身体缓冲，随后整理前爪或尾巴 | 否 |
| 暂时失败 | 耳朵稍降，不闪烁、不抖动，随后回待机 | 否 |

表情只需提供关键替换图层，不需要预先画完整逐帧动画。呼吸、眨眼、关节摆动和视线跟随由程序完成。

## 导出文件

手绘方案导出透明 PNG；矢量方案导出 SVG。文件名使用小写英文和连字符，例如：

```text
assets/mascot/cat/body.png
assets/mascot/cat/head.png
assets/mascot/cat/front-paw-left.png
assets/mascot/cat/tail-01.png
assets/mascot/cat/rig-guide.png
```

`rig-guide.png` 仅供开发定位，不在网页展示。每次导出必须保持相同画布、相同缩放和相同位置，不要对单个部件自动裁边。

## 网页接入结构

PixiJS 负责组合和显示各部件，Matter.js 负责重力、关节约束、弹簧和阻尼。鼠标、触摸与手势统一映射为三个动作：

```text
mascotGrabStart(x, y)
mascotGrabMove(x, y)
mascotGrabEnd()
```

抓取期间不打断文字回答或语音识别。松开后根据离地高度决定原地回弹或短距离落下；速度和关节角度必须设上限，避免快速甩动导致部件穿插。启用“减少动态效果”时，四肢只做小幅缓动，不运行明显弹跳。

## 交付前自检

- 缩小到 160 px 后，眼睛、四只脚和尾巴仍能辨认。
- 所有关节旋转 25–40 度后没有露缝。
- 左右部件名称与画面方向一致。
- 透明边缘没有白边或底色残留。
- 原稿、导出图和 `rig-guide` 使用完全相同的画布。
- 不把阴影画死在身体图层中；落地阴影由网页根据高度实时生成。

## Godot 版本网页接入（当前实现）

当前网页角色直接来自 Godot 4 场景 `D:\godotWork\cat-anim\node_2d.tscn`。原 Godot 工程只作为美术与骨骼源文件，导入命令不会修改它，也不需要把整个 Godot Web 导出包嵌入网站。

在项目根目录执行：

```powershell
npm run mascot:import-godot
npm run mascot:test
```

第一条命令读取 `.tscn`，复制场景使用的透明 PNG，并生成网页运行时清单：

```text
assets/mascot/cat/rig.json
assets/mascot/cat/*.png
```

网页由 `js/mascot/cat-mascot.js` 使用 Canvas 2D 重建骨骼层级。它支持待机、唤醒、聆听、思考、回答、错误和被拎起状态；鼠标、触摸与站内虚拟手势指针使用同一套 Pointer Events。拖动超过阈值后不会误触打开智能体，松手后角色会弹性回到浮动位置。

维护规则：

- 调整 Godot 里的贴图、层级或骨骼后，重新执行上述两条命令。
- 不要手工编辑生成的 `rig.json`，否则下次导入会被覆盖。
- 若源场景迁移，可把新路径作为参数传入：`node scripts/import-godot-cat-rig.mjs D:\path\to\scene.tscn`。
- 部署时必须同时上传 `assets/mascot/cat/`、`js/mascot/cat-mascot.js`、`js/mascot/companion-dialogue.js`、`js/agent.js` 和 `css/main.css`。

## 自然交互角色系统

当前实现分为两层，后续替换小猫形象时应继续保持这一边界：

- `js/mascot/cat-mascot.js`：只管理 Canvas 绘制、骨骼状态机、视线、抓取、重力和自主行为。
- `js/mascot/companion-dialogue.js`：只管理剪纸/皮影人设、情境短句、气泡定位和完整智能体入口。

主小猫支持 `idle`、`walking`、`sleeping`、`grabbed`、`falling`、`fallen`、`listening`、`thinking`、`speaking` 和 `error` 状态。外部模块不要直接改变 Canvas 或骨骼角度；需要新增情境反馈时统一调用：

```js
agent.react('district', {
  id: 'jiading',
  name: '嘉定区',
  heritageOverview: '嘉定竹刻、徐行草编等项目……',
});
```

当前语义事件包括 `district`、`craft`、`step`、`action` 和 `graph`。短气泡只提供一条克制的当前线索，用户点击“继续问小蕉”后才打开完整智能体面板。

动画也可通过组件 API 或 DOM 事件复用：

```js
mascot.play('walk');
mascot.play('sleep');
mascot.element.dispatchEvent(new CustomEvent('mascot-command', {
  detail: { type: 'tap' },
}));
```

新增 Godot 骨骼后，只需在 `stateTargets()` 中为新骨骼补充目标角度；页面事件和气泡模块无需跟随修改。眼睛是独立贴图层，运行时只施加最多约 5 个 Godot 像素的位移，避免视线跟随显得突兀。

当前动作参数说明：

- 原始小猫朝向画面右侧；行走方向为左时才使用 `scaleX(-1)`，不要把腿部相位与身体镜像分别反转。
- 页面占位盒与动画画布相互独立：占位盒负责点击、拖动和页面布局，扩展画布负责容纳旋转后的头、身体与尾巴。不要再用扩大占位盒或按状态切换画布视口的方式解决裁切。
- 所有姿态共用同一个相机变换和头部屏幕坐标；抓取只允许围绕 `grabBone` 旋转。画布尺寸必须读取 `clientWidth/clientHeight`，不能读取会受悬停缩放影响的 `getBoundingClientRect()`。
- 休息状态使用 `stateOffsets()` 下移根骨 `hip`，让身体、四肢和尾巴作为整体降低，再用关节角度把四肢铺平；禁止只移动胸部或腿部，也禁止使用非等比画布缩放。
- 抓取状态以 `HANG_BASE_ANGLE` 提供身体基础下垂角，头部和四肢分别反向补偿，横向拖动速度只叠加钟摆惯性。
- 尾巴四节使用不同相位、弹簧刚度和阻尼；点击、说话、行走与抓取都有独立目标，避免整条尾巴同步旋转。
- 待机耳朵约每 8 秒出现一次低幅随机感抖动；点击耳朵动作属于瞬时状态，不覆盖聆听、思考等智能体状态。
- 行为与情境语料集中维护在 `companion-dialogue.js` 的 `messageFor()`，页面不得直接写死气泡文案。

`scripts/smoke-cat-mascot-ui.mjs` 会检查头部锚点在待机和抓取状态下是否一致，并检查旋转后的姿态是否越出扩展画布。替换 Godot 模型后必须运行该测试；这两项失败时应检查坐标系、画布和骨架，不要通过单个姿态偏移临时掩盖。

## 关系驱动的自主行为架构

第二阶段把“小猫有多熟悉用户”“下一次做什么”和“骨骼怎样执行动作”拆成三个边界清晰的模块：

- `relationship-store.js`：保存关系分数、按时间衰减、限制短时间重复刷分，并将连续分数映射为五个相处阶段。存储不可用或数据损坏时回到安全初始值，不影响小猫显示。
- `behavior-brain.js`：纯函数决策层。根据相处阶段、可用平台和“减少动态效果”设置，对候选行为做条件过滤与加权随机选择。它不接触 DOM、Canvas 或存储，可单独做确定性测试。
- `cat-mascot.js`：动作执行层。只接收决策并运行行走、环顾、伸展、深睡、开心摆尾、快速跑动和跳跃等骨骼表现；页面或智能体仍可通过 `play()` 主动控制动作。

关系分数不直接展示。智能体面板只显示五枚圆点与阶段文案：从“你和小蕉刚熟悉”逐步变化到“小蕉很喜欢跟你玩”。提问是主要正向事件，点击、抓取、唤醒和打开面板只提供较小增量；每类事件有独立冷却时间。分数每天缓慢下降，长期没有互动时动作池也会回到较安静的状态。

自主行为遵循以下稳定性规则：

- 一级只开放环顾、普通行走、短睡和伸展；关系提高后才逐步开放开心摆尾、快速跑动、平台跳跃与庆祝跳跃。
- 深睡是低概率事件，不设置自动结束时间，只能由点击或智能体外部状态唤醒。
- 平台跳跃只从页面提供的最多两个安全行走面中选择更高的平台；没有合格平台时不会凭空创建碰撞目标。
- 启用“减少动态效果”时，决策层直接排除快速跑动与跳跃，而不是只把动画速度调慢。
- 外部的聆听、思考、回答和错误状态始终比自主行为优先，避免回答过程中突然睡觉或跳走。
