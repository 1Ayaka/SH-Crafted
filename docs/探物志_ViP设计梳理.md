# SH-Crafted 的 ViP 设计梳理

> 本文使用 ViP（Vision in Product）方法，梳理 SH-Crafted 的设计预见、设计声明与交互方式。它不是功能列表，而是后续产品决策的判断依据。

## 一、项目对象

SH-Crafted 是一个面向公众的上海非物质文化遗产数字体验平台。它同时承担三件事：

- 让用户发现和理解非遗项目；
- 让用户通过工序、材料、模型和影像感知技艺；
- 让用户提交资料，由项目协作者审核、编辑并持续维护。

平台的核心不是“展示八个项目”，而是建立一条可持续的内容链路：

```text
用户发现 / 提交资料 → 协作者审核与编辑 → 统一数据源 → 公众探索与学习
```

这里的“协作者”指负责内容审核和维护的同一位内容专家，不再区分专家端与管理员端。

## 二、未来情境：设计预见

### 1. 人们面对的未来

未来的非遗传播不再主要发生在展柜、说明牌或一次性的线下展览中，而发生在一个持续更新的数字环境里。人们可能在很短的时间内，从地图上的一个地点、星图上的一个节点、一张工艺图片或一段声音进入一项技艺。

他们面对的不是“缺少内容”，而是三种距离：

- 与技艺的距离：只看名称和结论，却不了解它如何被做出来；
- 与传承人的距离：看见成品，却看不见人的经验、判断和时间；
- 与可信资料的距离：网络资料很多，却难以知道哪些内容经过核验、哪些仍在补充。

### 2. 我们的判断

非遗数字化的价值，不是把传统技艺搬成一个更大的资料库，而是把原本断裂的“地点、人物、材料、工序、作品和记忆”重新组织成可探索的关系。

因此，SH-Crafted 的设计预见是：

> **未来的人们会通过探索关系来理解非遗，而不是通过阅读一页孤立的介绍来记住非遗。**

平台应当让一次偶然的发现，逐渐变成对技艺脉络的理解；让资料的新增与修订留下清晰痕迹，而不是覆盖掉过去的判断。

### 3. 预见带来的产品要求

- 入口可以是地图、星图、图片、声音或工序，但最终都能回到同一项非遗的统一资料；
- 内容要呈现“成品背后的过程”，而不是只展示漂亮结果；
- 星图只显示当前理解所需的有限关系，避免用全部数据压垮用户和设备；
- 每一条公开内容都应能追溯到已审核的版本；
- 新提交内容应进入待审核状态，不能直接覆盖协作者已经确认的内容。

## 三、设计声明：我们的立场与意图

### 核心声明

> **SH-Crafted 不替用户讲完非遗，而是给用户一条可以自己走出的理解路径。**

我们希望用户离开平台时，不只记住一个项目名称，而是形成三个认识：

1. 这项技艺与什么地方、材料和生活有关；
2. 一件作品经过了哪些选择和工序；
3. 今天仍然是谁在维护、实践和继续改变它。

### 内容立场

- 真实性优先于视觉完整：缺少证据的内容应明确标注，而不是用推测填满界面；
- 过程优先于结论：允许用户沿工序、材料和相似技艺慢慢理解；
- 人优先于抽象分类：传承人、社区和使用场景不能被隐藏在标签之后；
- 可持续维护优先于一次发布：内容应能被补充、修订、回溯和恢复；
- 克制优先于堆叠：星图和详情页只在当前情境下显示有意义的信息。

### 品牌语气

平台的语气应当像一位可靠、耐心的地方讲述者：准确但不生硬，亲近但不轻浮，允许用户停留、比较和返回。视觉上使用留白、材料感和有限的色彩层级，避免把非遗包装成快速消费的“奇观”。

## 四、交互方式：让声明发生在产品里

### 1. 入口交互：从偶然发现开始

- 地图页是“在上海寻找技艺”的入口，用户可以按地点、类别和项目探索；
- 星图总览页展示有限数量的主非遗节点，节点随机分布但关系线保持克制；
- 点击总览节点才进入具体非遗，不在总览页预先塞入详情和无效子节点；
- 图片、声音、模型或工序卡片都可以成为进入点，并带出项目之间的相关关系。

### 2. 关系交互：从一个项目向外理解

- 进入一个主非遗后，默认显示第一级的三个关键关联；
- 用户主动点击后，再展开一级次级关系，最多两级；
- 每次展开都说明关系类型，例如“共享材料”“相近工艺”“同一区域”或“相关人物”；
- 无关节点不因数据存在就显示，关系必须服务于当前的理解任务；
- 点击任一节点，都可以回到该节点自己的资料页，而不是打开一份临时拼接的内容。

### 3. 工艺交互：从看成品到理解过程

- 工序以横向、可回看的阶段组织，用户可以按顺序进入，也可以跳转比较；
- 工作台保留必要的操作空间，纪录片片段只在存在且与当前工序相关时出现；
- 图片、模型、材料和声音不是装饰，而是解释某个动作或判断的证据；
- 手势交互用于拖动、旋转和浏览，不承担唯一操作路径，所有关键动作同时提供鼠标、触控和键盘方式。

### 4. 内容交互：从提交到可信发布

- 用户通过表单或标准 JSON 提交项目、图片、说明、星图关系和工序资料；
- 系统先校验必填字段、图片数量、资源格式和关系引用；
- 提交内容进入待审核版本，公开版本保持不变；
- 协作者在管理端用表单、图片拖拽和节点编辑器修改内容，不要求直接维护 JSON；
- 审核通过后生成新的公开版本，并保留旧版本和变更记录；
- 管理端可以预览“本次修改”和“当前线上版本”的差异，再决定发布。

## 五、统一数据原则

ViP 要求产品形态服从同一个判断，因此用户端、管理端和公开展示必须维护同一份规范化数据，而不是各自保存一套相似字段。

### 数据状态

```text
draft（草稿） → pending_review（待审核） → published（已发布）
                                      ↘ rejected（退回修改）
published → archived（历史版本）
```

### 版本保护

- 用户导入只能创建草稿或待审核版本；
- 管理端编辑以当前公开版本为基线生成新版本；
- 发布新版本采用整包校验和原子替换，不能部分覆盖线上数据；
- 图片、模型、星图节点和工序均使用稳定 ID，更新内容不改变既有 ID；
- 已审核版本只读保存，任何新导入都不能直接覆盖；
- 发布前必须检查资源是否存在、引用是否有效、关系是否形成闭环。

## 六、用 ViP 校验后续设计

以后新增一个功能时，先回答以下问题：

1. 它对应了哪一种未来情境，帮助用户理解了什么关系？
2. 它是否让用户更接近技艺过程和真实的人，而只是增加信息数量？
3. 它是否使用统一数据源，并能被协作者审核和回溯？
4. 它是否有克制的默认展示，避免一次性显示全部关系？
5. 没有手势、模型或网络时，用户是否仍能完成核心任务？

如果一个功能无法回答这些问题，它就可能只是功能堆叠，还没有成为 SH-Crafted 的产品交互。

## 七、一句话版本

> **让人从上海的一处地点或一件作品出发，沿着真实的技艺关系走近非遗；让每一次新增与修订都被看见、被审核，并成为下一次探索可靠的起点。**
