# 上海非遗交互系统——正式开发产品大纲

## 1. 项目定位

面向大众的上海非遗互动网页。系统以竞赛官方开放数据为基础，通过上海地图、地区探索、3D 工艺体验和智能讲解，让用户了解非遗的地域分布、文化背景与制作过程。

项目主张：

> **从地图看上海手艺。**

产品说明：按地区浏览非遗项目，查看工序与影像资料，并在交互工作台中完成一次简化制作。

## 2. 内容范围

- 首版展示 **8 门上海非遗工艺**，完成可体验、可检索、可追溯的闭环。
- 首版优先覆盖现有视频资料较完整的地区；后续再逐步增加行政区和项目，不为覆盖数量强行填充。
- 工艺选择优先考虑：地域代表性、官方数据完整度、视觉辨识度和互动制作可行性。
- 8 门工艺都有基础详情，其中选择少量重点项目制作完整 3D 工艺体验，其余使用图片、视频、局部模型或简化交互呈现。

建议的内容层级：

| 层级 | 数量 | 完成程度 |
|---|---:|---|
| 全部工艺 | 8 门 | 地区、类别、简介、历史、传承与资料来源 |
| 重点工艺 | 2—3 门 | 增加精细模型、工艺拆解或较完整互动 |
| 核心样板 | 1 门 | 完整 3D 制作流程与智能体全程引导 |

## 3. 用户体验主线

首页与地图页拆成两个独立页面。首版没有完成转场动画时，保留动画容器和状态接口，但不以占位动画阻塞主要功能。

```text
首页：理解网站用途
  → 点击“进入地图”
  → 上海地图远景
  → 悬停行政区，查看竹简式非遗列表
  → 点击行政区，镜头下降并进入地区探索状态
  → 点击贴近地图表面的非遗图片或名称，右侧滑入项目简介
  → 点击“成为传承人”，进入非遗详情与工艺体验页
  → 阅读工艺概览、工序与材料、人与作品
  → 进入工作台
  → 选择一种或多种材料与物件、执行动作、完成流程组合
  → 查看粒子成品、代表作品和纪录片证据
  → 按需唤出小蕉智能体继续了解
```

## 4. 页面结构

### 4.1 首页

- 首页路由与地图页分离，建议使用 `/` 和 `/explore`。
- 首页必须先说明产品用途：基于官方开放数据和纪录片资料，以地图、工艺互动和可追溯智能讲解帮助用户认识上海非遗。
- 首屏保留项目名称、1 段简短说明、“进入地图”主按钮和“资料来源”次入口。
- 小蕉不再作为首屏主角，只可作为智能讲解入口的小型识别图形出现，面积和视觉权重低于标题与主按钮。
- 首页第一层画面按真实显示像素的明暗分布，在左下与右上两处集中布置较大的水墨图片精灵：荷花只保留 2—3 朵，其余全部使用荷叶，中部内容区不铺满；鼠标经过会将其像水面漂浮物一样划开并缓慢回位，点击空白处会触发由点击点扩散的离场波纹，再平滑进入地图页。
- 首页与地图页的转场使用 `home_exit`、`map_enter` 两个状态；导航、资料按钮和管理控件保持标准点击行为，不触发空白区粒子爆发。
- 首屏不得虚构非遗数量、覆盖地区或成果数据；统计信息只有在接入真实数据后才显示。

### 4.2 上海非遗地图：远景状态

- 初始镜头距离较远，以立体俯瞰方式完整呈现上海行政区组合关系。
- 行政区模型由用户提供时，最推荐交付一个已经摆好相对位置的总模型；每个区是独立命名节点，程序据此绑定行政区数据和交互。详细资产规范见第 11 节。
- 地图页不渲染独立粒子，项目数量、类别和资料完整度通过区块高亮、项目图片按钮、列表和右侧简介表达；成品粒子仅在详情页出现，并明确标注为模型展示效果。
- 鼠标悬停行政区时，目标区块明显上浮，极淡玉灰边界适度增强，其他区域轻微降低对比度；地图页不再渲染边缘粒子瀑布，避免遮挡地图与项目按钮。粒子仅用于详情页成品揭晓，使用真实模型贴图颜色并以轻微下坠、渐隐和补回表现材质呼吸。
- 同时在区块附近展开竹简式浮层，列出该区已有数据支持的非遗项目。竹简横向或纵向舒展，但文字保持正常排版，不使用难读的仿古字体。
- 若该区已有地标模型，则在区块上显示地标的粒子外轮廓；没有地标资产时不生成虚构建筑，只保留接口和空状态。
- 有无已接入非遗项目不影响行政区点击；无项目区仍可进入并阅读区名由来、地区特色和非遗概览。
- 进入地区后点击空白区域、按 `Esc` 或选择“返回上海全景”可恢复远景；若项目简介已打开，第一次点击空白先关闭项目简介，再次点击返回全景。
- 提供地区搜索、类别筛选、地图/列表切换；低性能设备默认使用列表和静态边界版本。

### 4.3 地区探索：近景状态

- 点击行政区后不跳转到普通卡片页，而是在同一 3D 场景中执行镜头过渡：镜头向下移动并放大，俯视角逐渐过渡为斜俯视或接近平视。
- 这里表达的是“进入地区空间”，不是自动生成真实街道。若后续希望达到身处街道的效果，需要额外提供道路、街区或地标资产；只有行政区块模型时，应呈现为半透明的空间地台。
- 当前区块放大并半透明化，其他行政区隐藏或降低为远景轮廓。
- 该区非遗项目以带图片和名称的按钮贴近地图顶面显示，锚点来自区块包围盒和配置数据，不随瀑布粒子尺寸漂移，也不做无意义随机移动。
- 点击项目图片或名称后，右侧滑入项目简介窗口；左侧地区介绍从左侧滑入。关闭时分别向原方向淡出滑走，避免硬切。
- 项目简介窗口内提供居中的“成为传承人”按钮，点击后才进入详情页；同时保留列表入口，保证用户不依赖精确鼠标操作也能找到项目。
- 触屏设备用第一次点击显示简介、第二次点击进入详情；开启减少动态效果后，以高亮和淡入替代上浮、散开和长镜头运动。

### 4.4 非遗详情与体验页

页面采用左右双区布局：左侧为资料阅读区，右侧为粒子工作台。默认状态下资料区约占 35%—40%，体验区占其余空间；实际比例需根据分辨率自适应。

左侧由三块可折叠内容组成：

1. **工艺概览**：历史背景、用途、地域和保护信息。
2. **工序与材料**：材料、物件、动作、步骤和关键技法；“进入工作台”旁提示“建议先查看工序”。
3. **人与作品**：人物、代表作品、文化趣闻、相关项目和资料中可核验的有趣信息。

三块面板使用“中国画叠山”作为布局隐喻：点击其中一块时，该面板展开，另外两块向下收拢为仅显示标题的层叠形态。不得让折叠动画影响正文滚动或键盘操作。

右侧为粒子状工作台：

- 未开始时显示工艺代表物的粒子轮廓、“进入工作台”按钮和体验说明。
- 点击开始后，左侧三个面板整体向左收起，工作台扩展；始终保留可恢复资料区的明确按钮。
- 右侧资源区显示当前项目中的材料与可复用物件；用户可多选资源，再独立选择动作。图标、名称、状态和来源由结构化工艺数据生成。
- 工艺模拟必须注明“基于纪录片与审核资料简化，不构成真实工艺教学”。

### 4.5 工艺体验状态机

工艺操作按结构化步骤运行，核心流程为：

```text
阅读资料
  → 进入工作台
  → 选择一种或多种材料与物件
  → 选择动作
  → 点击“执行动作”
  → 规则引擎判断当前组合与步骤
  → 显示原理说明和纪录片证据
  → 材料状态更新
  → 所有工序执行完成
  → 将工序填入流程图
  → 校验顺序与组合
  → 完成作品并进入成果展示
```

- 工艺步骤是否正确由经人工审核的 `process_steps` 规则即时判定，不能让大模型自由决定。
- 智能体在每次动作执行后检索与当前步骤绑定的知识和纪录片证据，解释为什么这样处理，并可打开对应视频时间段。
- 多阶段材料使用状态链记录，例如“原料 → 初加工 → 中间态 → 可装配”，背包中必须明显区分状态。
- 流程图错误时指出冲突位置，但不直接给出全部答案；连续失败后提供分级提示。
- 正确完成后生成可旋转、缩放的粒子成品模型；背包区域切换为代表作品图片列表，图片必须显示名称和来源。

### 4.6 小蕉智能体

- 小蕉仅作为智能体形象出现，不再承担首页主角、地图引路、转场或完成庆祝等高占比表演。
- 默认以侧边按钮或局部猫耳标识存在；支持拖拽展开、单击展开、键盘操作和移动端按钮。
- 智能体展开时，左侧资料面板收起或保持标题态，工作台保留足够空间；用户重新展开左侧资料时，智能体自动收起。两者由统一的面板管理器控制，避免相互遮挡。
- 智能体读取当前页面、工艺项目、步骤、背包物品、最近操作和失败次数作为会话上下文，不读取无关个人信息。
- 用户多次失败时，小蕉先以非打断方式提示“要看一条提示吗？”，用户确认后再给解释或播放纪录片片段。
- 回答只使用官方数据、审核知识和本次检索到的证据；资料不足时明确说明，引用可跳至视频时间码。
- 小蕉的人设是“一只正在收集上海非遗资料、愿意分享所见技艺的小猫”，不冒充传承人，也不替代专业教学。

## 5. 视觉与交互风格

视觉方向锁定为 **Organic（有机数字展陈）**：传统文化内容通过自然材质、柔和空间和缓慢呼吸式运动呈现，不混入霓虹赛博、玻璃拟态或游戏 HUD。中国画意象主要体现在留白、叠山结构和墨粒聚散，而不是堆砌古典纹样。

- **主表面**：砂色 `#E8DCC7`，避免纯白和常见浅奶油色。
- **结构色**：苔绿 `#606C38`、鼠尾草绿 `#8B9D83`。
- **提示色**：赭石 `#C08E3A` 或陶土 `#C66B3D`，只用于当前步骤、错误位置和可操作状态。
- **深色**：使用深松墨色替代大面积纯黑；小蕉可保留深色剪影，但不占据主要视觉面积。
- **字体**：标题使用现代宋体或人文衬线方向，正文和控件使用清晰黑体；标准按钮使用“进入地图、进入工作台、返回、确认、查看影像”等直接文案。
- **形态**：内容面板采用 16—24 像素圆角；地图区块、竹简浮层和叠山面板共享统一的柔和边缘语言。
- **质感**：允许 1%—3% 的纸面颗粒，但不影响文字和 3D 模型清晰度。
- **运动**：常规过渡 300—500 毫秒；长镜头运动必须可中断，并为减少动态效果模式提供淡入替代。

贯穿全站的标志性交互是 **“有依据的墨粒聚散”**：粒子聚成行政区、项目、材料状态或成品时都对应真实数据与操作状态；筛选和离场时再散开。它既是视觉记忆点，也是数据状态的表达方式。

## 6. 数据使用

数据不能只出现在智能体问答里，而应直接决定地图、空间、交互规则和结果展示。

| 数据 | 页面中的实际用途 |
|---|---|
| 行政区与项目归属 | 上海地图绑定、地区筛选和镜头进入目标 |
| 项目数量与类别 | 地图粒子密度、图例、竹简列表和地区统计 |
| 纪录片时间码 | 工艺步骤解释、失败提示、证据浮窗和片段跳转 |
| 材料、物件、动作、步骤顺序 | 资源列表、组合规则、状态变化和流程图答案 |
| 人物、机构、年代 | 详情页、关系推荐和智能体事实回答 |
| 代表作品图片 | 完成后的作品列表与来源说明 |
| 数据完整度与审核状态 | 页面是否允许公开、智能体是否回答、是否显示“资料待核验” |

建议增加“数据护照”入口，用户和评审可查看：来源机构、授权范围、原始资料、处理模型、人工审核状态、关联视频和更新时间。每条工艺步骤都应有“为什么这样做”和“查看纪录片片段”入口。

外部图片、视频、声音和 3D 模型必须记录来源、授权和加工方式；AI 生成描述标记为衍生内容，不能覆盖原始资料。

详细流程见：[上海非遗视频数据处理与知识库方案](./上海非遗视频数据处理与知识库方案.md)。

## 7. 初步实施顺序

1. 确认官方数据、首版项目、纪录片证据和授权范围。
2. 完成上海地图主模型导入、16 区命名校验、远景悬停和近景镜头状态。
3. 完成首页与地图两条独立路由；动画槽位只预留接口。
4. 选择 1 门工艺实现详情页、三段叠山面板、背包和工作台状态机。
5. 用审核后的结构化步骤实现规则判定，再接入证据检索和小蕉智能体。
6. 完成作品展示、数据护照和引用视频播放器。
7. 扩展 2—3 门重点工艺，再补齐其余项目的基础详情。
8. 最后优化粒子、地标轮廓、移动端和低性能降级版本。

## 8. 当前最需要确定的问题

- 地图资产是一个包含 16 个独立节点的总模型，还是 16 个保持统一坐标的单独模型。
- 是否有道路、街区或地标资产；若没有，近景阶段按“空间地台”而非真实街道实现。
- 官方数据能否支持 16 个区的真实列表，资料不足的区如何展示空状态。
- 首版 8 门工艺的正式名称、地区、项目级别和选择依据。
- 哪一门工艺具备完整、已审核的资源—动作—状态—成品数据，可作为核心体验样板。
- 工艺步骤、模型、作品图片和纪录片片段的授权范围。
- 目标设备的性能范围，以及粒子、地标和镜头动画的降级方式。
- 智能体使用本地模型还是服务器模型；比赛现场断网时如何降级为审核知识和固定证据检索。

## 9. IP 形象：小蕉

### 9.1 基本设定

小蕉只承担智能体形象，不再承担全站叙事和大面积动画。它是一只正在收集上海非遗资料、愿意与用户分享所见技艺的小猫。

- 轮廓保持简洁深色剪影，暖黄色眼睛作为小面积识别点。
- 不穿复杂古装，不佩戴固定传统工艺服饰，不冒充传承人。
- 性格好奇、耐心、克制；优先解释证据，不替用户完成操作。
- 它可以说“有一段相关影像，可直接查看”，不应说“我就是这样制作的”。

### 9.2 出现范围

- **首页**：仅可作为“智能讲解”能力的小型图形或说明，不作为主视觉。
- **地图与地区探索**：默认不出现。
- **详情与工作台**：以侧边按钮、猫耳或头像作为智能体入口。
- **用户求助与连续失败**：展开后提供分级提示、原理解释和纪录片证据。
- **完成作品**：不强制播放小蕉庆祝动画，优先保证成品模型和资料来源成为视觉主角。

## 10. 首批推荐的 8 门工艺

以下项目根据当前《数据说明》中的内容和影像资料筛选，优先考虑视觉辨识度、互动步骤和资料可转化程度。最终名称、行政区和项目级别仍需与官方数据集逐条核对。

| 项目 | 地区 | 适合的交互形式 | 推荐理由 |
|---|---|---|---|
| 月份牌年画——擦笔水彩年画技法 | 静安 | 分层上色、笔触互动、前后对比 | 色彩和笔触明显，适合水墨与彩墨粒子表现 |
| 七宝皮影艺术 | 闵行 | 皮影拼装、灯光与剪影控制 | 能把 3D、光影、角色动作和故事结合起来 |
| 嘉定竹刻 | 嘉定 | 竹面雕刻、纹样描摹、局部放大 | 工具、纹样和成品关系明确，适合核心 3D 样板 |
| 药斑布印染工艺 | 嘉定 | 纹样选择、包扎/印染、展开成布 | 适合做图案生成和结果对比，视觉传播性强 |
| 毛氏风筝制作技艺 | 奉贤 | 骨架组装、蒙面、风向与放飞 | 制作和动态效果结合，适合“完成后放飞”反馈 |
| 南桥撕纸技艺 | 奉贤 | 撕、挖、扯的手势互动、图案生成 | 用户动作与传统技法对应直接，入门门槛低 |
| 牙雕方向（正式名称待核对） | 待以官方数据集确认 | 材质观察、局部雕刻、细节放大 | 适合做精细 3D 展示和局部雕刻互动；当前数据说明中明确出现的是“象牙篾丝编织”，需确认是否为同一项目或相关项目 |
| 崇明土布纺织技艺 | 崇明 | 纺线、经纬排列、纹样织造 | 工序丰富，可做长期扩展项目和数据叙事 |

### 10.1 推荐的核心样板

首个完整 3D 样板建议在以下两个项目中选择：

- **嘉定竹刻**：最适合体现“材料与物件—动作—纹样—成品”的完整链路。
- **南桥撕纸**：操作简单、反馈直观，更适合大众首次体验。

如果希望突出材质和视觉表现，可选择嘉定竹刻；如果希望降低开发难度、快速验证交互闭环，可选择南桥撕纸。

### 10.2 后续扩展

完成首版 8 门后，可根据数据完整度和素材授权情况逐步扩展到 12 门，再评估是否增加到 16—20 门：

- 调香技艺：香料选择和配方关系。
- 上海漆器／海派漆艺：器形、材质和分层髹饰。
- 徐行草编：材料选择和编织路径。
- 马陆篾竹编织工艺：劈篾、交错编织和结构拆解。
- 七宝方糕或庄行青团制作技艺：食物制作流程体验。
- 庄行织带技艺：经纬编织和色彩搭配。
- 崇明灶花：锅底灰调墨与墙面绘画。
- 益智图：拼合、旋转和图形生成。
- 郁金香酒酿造工艺：原料、配方和时间流程可视化。
- 莘庄结花边：线材路径和图案生成。

补充项目不应为了凑数量而加入；若缺少可靠的工艺步骤、影像或授权素材，应先作为基础详情展示。

## 11. 上海地图模型交付规范

### 11.1 推荐交付方式

用户可以在 Blender、Maya 或其他软件中把 16 个行政区的相对位置摆好并命名。最推荐导出为一个 `shanghai_map.glb`：

```text
shanghai_map
├─ district_huangpu
├─ district_xuhui
├─ district_changning
├─ district_jingan
├─ district_putuo
├─ district_hongkou
├─ district_yangpu
├─ district_minhang
├─ district_baoshan
├─ district_jiading
├─ district_pudong
├─ district_jinshan
├─ district_songjiang
├─ district_qingpu
├─ district_fengxian
└─ district_chongming
```

每个行政区必须是可单独选择、移动、变透明和绑定事件的独立节点，不能合并为一个网格。节点名称使用稳定英文 ID，页面显示的中文名称由数据表提供。

### 11.2 坐标与模型要求

> 当前 v1 实现使用 `assets/models/上海map_v2.glb`：模型按历史名称提供 11 个可交互行政区节点，并额外提供“以外的陆地”灰色环境节点；运行时节点白名单见 `js/map3d.js`。下列 16 区规范作为后续切换现行行政区模型时的交付标准保留。

- 16 个区使用同一世界坐标、单位、缩放和朝向；应用变换后再导出。
- 如果分成 16 个文件导出，必须保留共享全局坐标，不能把每个区单独移动到原点。
- 统一规定 Y 轴向上，建议 1 个模型单位对应统一的实际或设计尺度。
- 每个区设置合理轴心，悬停上浮时沿 Y 轴移动，不发生横向漂移。
- 主地图采用低面数网格；边界描边、粒子和地标使用独立对象或程序生成。
- 交付 GLB/glTF，纹理使用压缩格式；避免直接以 FBX 作为网页最终格式。
- 为每个区提供简化碰撞网格，确保鼠标命中稳定。

### 11.3 地标与非遗锚点

- 地标建筑作为行政区节点的子节点或独立 GLB，命名如 `landmark_jiading_fahua_tower`；正式名称必须来自真实资料。
- 地标粒子轮廓只在资产存在时显示，不自动虚构城市天际线。
- 非遗项目在地区空间中的位置由配置文件保存：`district_id`、`craft_id`、`position`、`height`、`featured`。
- 如果没有可靠地理坐标，可使用“策展空间位置”，但需要在数据说明中标注它不是实际地址。

### 11.4 导入验收

- 16 个区数量与命名完全匹配。
- 无重叠缝隙导致的错误点击，崇明等离散区域保持正确关系。
- 任一区块能独立上浮、透明化、隐藏和恢复。
- 总模型在目标设备保持稳定帧率；高面地标提供低模或关闭开关。

## 12. 页面与交互状态

系统应使用明确状态控制镜头、面板和智能体，避免多个动画互相争夺布局。

| 状态 | 主要画面 | 左侧资料 | 智能体 | 用户可执行操作 |
|---|---|---|---|---|
| `HOME` | 首页说明 | 不显示 | 小入口 | 进入地图、资料来源 |
| `MAP_OVERVIEW` | 上海地图远景 | 不显示 | 不显示 | 悬停地区、筛选、列表切换 |
| `DISTRICT_HOVER` | 区块上浮、竹简展开 | 不显示 | 不显示 | 浏览本区项目、点击进入 |
| `DISTRICT_FOCUS` | 地区近景、项目图片按钮与右侧简介 | 不显示 | 不显示 | 查看项目简介、返回全景 |
| `CRAFT_READING` | 详情双栏 | 展开一块叠山面板 | 侧边入口 | 阅读、进入工作台、提问 |
| `CRAFT_PLAYING` | 工作台扩大 | 收起 | 侧边入口 | 拖拽、加工、组合 |
| `AGENT_OPEN` | 工作台或详情保留主体 | 收起/标题态 | 展开 | 提问、查看证据、执行页面工具 |
| `CRAFT_COMPLETED` | 粒子成品与作品列表 | 可恢复 | 侧边入口 | 查看作品、证据、相关项目 |

面板仲裁规则：左侧资料和智能体不能同时占用完整宽度；展开其中一个会收起另一个，但工作台的当前物料和进度不能丢失。镜头运动中用户点击新目标时，应取消旧动画并从当前相机位置平滑转向。

## 13. 完整交互流程模拟

### 13.1 首次进入

1. 用户打开首页，看到项目名称、用途说明和“进入地图”。
2. 用户可以先查看资料来源，也可以直接进入地图。
3. 点击“进入地图”后显示地图远景；当前版本直接淡入，未来动画从预留状态接入。

### 13.2 地图探索

1. 用户移动到嘉定区，区块缓慢上浮，边界增强。
2. 嘉定区附近展开竹简浮层，只显示已接入数据的项目正式名称。
3. 若已提供地标模型，地标以粒子轮廓出现；否则保持干净的地图表面。
4. 用户点击嘉定区，镜头下降、拉近并由俯视过渡到斜俯视。
5. 嘉定区成为半透明空间地台，嘉定竹刻等项目以图片按钮贴近已配置锚点显示。
6. 用户点击嘉定竹刻图片或名称，右侧滑入正式名称、类别、审核简介与记录图片。
7. 用户点击右侧“成为传承人”进入详情页。

### 13.3 阅读与进入工作台

1. 页面左侧默认展开“工艺概览”，工序与材料、人与作品折叠为叠山标题。
2. 用户点击“工序与材料”，概览面板收拢，材料与物件、动作和步骤展开。
3. 用户点击右侧“进入工作台”，系统提示该体验经过简化，并建议先查看工序。
4. 用户确认后，左侧面板向左收起，工作台和背包扩大；已阅读状态被保留。

### 13.4 资源选择与动作执行

1. 资源区只展示来自真实资料的材料与可复用物件，不混入装饰道具。
2. 用户选择一种或多种资源，再选择一个动作，点击“执行动作”。
3. 规则引擎检查资源状态、资源组关系、动作和当前步骤：
   - 正确：材料进入下一状态，显示简短原理和“查看纪录片片段”。
   - 顺序不对：说明需要先完成哪个前置状态，不直接给出全部答案。
   - 资源不对：指出多余资源或缺少的资源组。
   - 动作不对：保留已选资源，只要求重新选择动作。
4. 用户点击证据，浮窗播放绑定时间段的纪录片，显示字幕原文和来源。
5. 每一步完成后更新主体材料与中间产物状态；可复用物件不被消耗。

### 13.5 流程组合与完成

1. 所有必需材料准备完成后，系统开放填空流程图。
2. 用户将工序卡放入对应顺序槽位，点击“完成”。
3. 错误时保留正确部分，只提示错误位置；连续失败时小蕉询问是否需要分级线索。
4. 正确时工作台粒子聚成成品模型，支持旋转、缩放和局部查看。
5. 右侧背包切换为代表作品图片列表；点击图片可查看名称、来源、年代等已有资料。
6. 用户可打开“操作回看”，查看自己的操作步骤及对应证据。

### 13.6 智能体协作

1. 用户从侧边拖出或点击小蕉，左侧资料区自动收起，智能体侧栏展开。
2. 智能体读取当前项目、步骤、背包状态、最近操作和失败次数。
3. 用户问“为什么这一步要先处理材料”，智能体检索审核知识并返回解释、引用和视频片段。
4. 用户点击左侧资料按钮，智能体收起，资料面板恢复；工作台状态完全保留。
5. 用户返回地图时，只保留必要的当前会话摘要，不把整段聊天带入其他项目。

## 14. 智能体设计亮点

智能体定位为“状态感知的非遗工艺讲解与证据助手”，而不是普通聊天框。

### 14.1 可读取的上下文

```json
{
  "page": "craft_experience",
  "craft_id": "来自正式数据的项目 ID",
  "current_step_id": "当前审核步骤 ID",
  "inventory_states": [],
  "recent_actions": [],
  "failure_count": 0,
  "open_evidence_ids": []
}
```

### 14.2 受控工具

- `retrieve_evidence`：检索当前问题相关的审核知识和证据片段。
- `play_video_evidence`：打开指定 `evidence_id` 的纪录片时间段。
- `highlight_inventory_item`：高亮当前步骤可能相关的背包物品，但不直接完成操作。
- `open_process_step`：展开左侧对应工艺步骤。
- `compare_related_crafts`：比较同地区、同材料或同工具的项目。
- `show_data_passport`：展示来源、授权、模型处理与审核状态。

工具调用必须经过服务端权限和参数校验。首版不开放自由网页搜索，避免把竞赛官方数据与未经审核的外部内容混合。

### 14.3 主动帮助规则

- 第一次失败：只显示局部错误反馈。
- 连续两次失败：小蕉以非打断方式询问是否需要线索。
- 连续三次失败：可提供原理解释和一个证据片段，但仍不自动完成。
- 用户明确拒绝帮助后，在当前步骤内不重复弹出。
- 所有事实性回答附引用；找不到证据时返回“现有资料无法确认”。

## 15. 结合比赛要求的增强建议

### 15.1 数据使用亮点

1. **数据驱动地图，不是地图贴卡片**：项目数量、类别和资料完整度直接控制地区状态、项目按钮和资料层级，并提供数据护照。
2. **纪录片进入操作闭环**：每个资源组合、动作和流程步骤都绑定真实视频时间码，用户可从操作直接跳回证据。
3. **个人体验回放**：完成后生成“操作—知识—证据”路径，展示用户哪些选择对应哪些纪录片和审核知识。
4. **跨项目关联**：从材料、工具、地区、人物和工艺动作建立关系推荐，而不是只推荐“猜你喜欢”。
5. **数据护照与版本**：评审可查看官方数据如何经过整理、模型抽取、人工审核，再进入地图和 3D 体验。
6. **资料不足也是数据状态**：缺少证据的项目明确展示“资料待补充”，不为视觉完整而编造内容。

### 15.2 智能体亮点

1. **理解用户正在做什么**：回答结合当前步骤、材料状态和失败历史。
2. **会操作页面但不替用户完成**：能打开步骤、播放证据、高亮物品和比较项目。
3. **证据优先**：回答引用纪录片字幕和时间码，点击即可回看。
4. **分级教学**：根据失败次数逐步提供提示，保留探索感。
5. **快慢两条路径**：材料、物件、动作和步骤等直接读取结构化数据；复杂历史问题再进行检索和生成。
6. **比赛现场可降级**：模型或网络不可用时，仍能使用审核知识、固定问答、规则引擎和证据播放器完成核心体验。

### 15.3 建议加入的评审演示

选择一门核心工艺，用三分钟展示完整闭环：

```text
地图数据定位项目
  → 进入地区空间
  → 阅读真实资料
  → 故意选择错误动作
  → 小蕉根据操作提供分级提示
  → 打开纪录片证据
  → 正确完成步骤
  → 查看成品和数据护照
```

这条演示同时证明地图、开放数据、3D 交互、智能体、视频知识库和可追溯性不是彼此独立的展示模块。

## 16. 开发与验收补充

- 所有悬停交互必须有点击、键盘或触屏等价操作。
- 镜头下降和粒子散开不可阻塞返回；按 `Esc` 始终返回上一层状态。
- 用户切换资料、智能体或工作台时，不丢失步骤和背包状态。
- 低性能模式关闭地标粒子和复杂散开效果，保留地图选择、工艺规则和证据播放。
- 关键交互记录匿名事件：进入地区、查看项目、步骤成功/失败、查看证据和唤出智能体，用于比赛后的可用性分析；不记录不必要个人信息。
- 对外页面优先显示经确认内容；自动抽取候选保留审核标记，并通过站内管理模式校订。
- 当前《数据说明》明确记录的是“象牙篾丝编织”，文档中的牙雕方向仍是候选，正式名称、关系和授权范围必须核对；数字展示不得被理解为鼓励现实象牙交易。

## 17. 站内管理与上线前协作

- 管理入口与访客网站共用界面；管理员登录后，可维护模块右上角显示“编辑/保存”，不再切换到独立 CMS。
- 首页、行政区与非遗项目的展示文字支持原位编辑；证据编号、纪录片抽取结果、知识库和模型保持只读。
- 每个非遗项目提供独立工序管理页：横向选择工序，可新增、删除、前移或后移工序，并维护材料、工具和多个可选操作。
- 每道工序必须指定一个正确操作，保存后直接进入用户工作台的规则判定。
- 线上编辑内容持久化到部署目录之外的 `content.json`，GitHub 更新不能覆盖；服务端采用单管理员会话、同源校验和版本冲突检测。
- 两位协作者同时修改时，后保存者遇到版本冲突必须刷新后重做，禁止静默覆盖。
- 具体登录、服务器配置、备份和恢复流程见《内容后台使用与部署.md》。
