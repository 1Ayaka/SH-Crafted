# 上海非遗视频数据处理与知识库方案

## 1. 背景

项目的主要数据来源是上海图书馆开放的非遗专题片。视频包含旁白、访谈、字幕、历史图片、工艺操作和成品展示，信息丰富，但无法直接用于地图统计、页面检索、3D 步骤设计和智能体问答。

因此，需要先将视频处理为带时间码、来源和审核状态的知识库，再让同一批知识服务于：

- 上海非遗地图和地区统计。
- 首版 8 门工艺的详情页面，并支持后续扩展。
- 重点工艺的 3D 制作流程。
- 智能讲解助手的问答、提示和推荐。
- 答辩中的数据来源说明与证据展示。

比赛要求作品基于官方开放数据进行创作，并关注数据使用度、来源授权、系统响应速度和智能体可追溯性。因此，本方案将“证据链”和“低延迟”作为核心设计目标，而不是只把视频转成一批文本向量。

## 2. 建设目标

### 2.1 总体目标

建立一套从视频到知识服务的完整链路：

```text
原始视频
  → 音视频解析
  → 带时间码的字幕、镜头和关键帧
  → 实体、事实、工艺步骤和关系抽取
  → 人工审核
  → 全文索引、向量索引和结构化数据库
  → 地图、详情页、3D 流程和智能体共同使用
```

### 2.2 具体目标

- 每条可用于回答的事实都能回到具体视频、时间段和字幕原文。
- 每个工艺步骤都能说明材料、工具、动作、结果和依据。
- 智能体不根据记忆自由补全事实，只依据检索证据回答。
- 用户可以点击引用，直接查看对应视频片段或关键帧。
- 查询阶段不进行视频转写和视觉分析，保证响应速度。
- 官方数据、人工整理和 AI 生成内容能够明确区分。
- 一次加工的知识可以被网站多个功能复用。

## 3. 数据范围

### 3.1 首期范围

- 首批处理产品方案中选择的 8 门工艺。
- 每门工艺优先处理与其直接相关的完整专题片。
- 同时保留地区、人物、历史背景和相关项目的必要片段。
- 系统稳定后先扩展至 12 门，再评估是否增加到 16—20 门工艺。

### 3.2 数据类型

| 数据类型 | 主要内容 | 主要用途 |
|---|---|---|
| 原始视频 | MPG、MP4 或其他原始格式 | 证据母本和片段回放 |
| 音频 | 旁白、访谈、环境音、工具声 | 语音转写、工艺声音体验 |
| 字幕 | 原字幕、自动转写、人工修订稿 | 全文检索和智能体证据 |
| 关键帧 | 工具、材料、人物、步骤、成品 | 页面配图、视觉检索和引用缩略图 |
| 元数据 | 标题、地区、项目、时长、来源、授权 | 筛选、统计和证据管理 |
| 结构化知识 | 实体、关系、事实和工艺步骤 | 地图、详情、推荐和 3D 流程 |
| 衍生文本 | 摘要、术语解释、问答 | 页面叙事和智能体检索 |

## 4. 数据要求

### 4.1 原始视频要求

- 保留原始文件，不覆盖、不转码替换母本。
- 为每个视频生成唯一 `video_id`。
- 记录文件名、格式、时长、分辨率、文件大小和内容哈希。
- 记录数据集名称、提供机构、授权范围和使用限制。
- 记录专题片名称、集数、非遗项目、行政区和拍摄年份；未知字段保留为空，不推测补齐。
- 统一生成网页播放版本，但播放版本与原始母本建立明确关联。

### 4.2 内容质量要求

- 自动转写必须保留词级或句级时间码。
- 人名、地名、年代、工艺术语和步骤顺序属于关键字段，必须人工核对。
- 访谈与旁白尽量区分说话人；无法确认姓名时只标注“旁白”“受访者”等角色。
- 画面字幕、题词、工具名称等需要通过 OCR 提取并复核。
- 关键帧应覆盖材料、工具、动作、成品和人物，避免只抽取镜头开头。
- 对音画不同步、方言、背景音乐过强和老视频噪声设置质量标记。

### 4.3 授权与合规要求

- 竞赛官方数据仅按竞赛授权范围使用，不擅自商业化。
- 对视频片段、截图、人物肖像、声音和外部资料分别记录授权状态。
- 不将受限视频或字幕提交给授权范围不明确的第三方服务。
- 对牙材工艺等敏感内容采用历史文化和数字展示表述，避免引导现实交易。
- 所有 AI 生成摘要、标签和解释必须标记为衍生内容，不能覆盖原始资料。

## 5. 数据分层

建议将数据分为五层，避免原始资料、自动结果和审核知识混在一起。

### L0：原始层

- 原始视频、原始字幕、数据说明和授权文件。
- 只读保存，使用内容哈希检查文件是否变化。

### L1：解析层

- 转码视频、分离音频、自动字幕、OCR 文本、镜头边界和关键帧。
- 保留处理工具、模型版本、参数和处理时间。

### L2：证据层

- 将视频切分为带时间码的证据片段。
- 每个片段包含字幕原文、关键帧、说话人和视频位置。
- 这一层是智能体引用的直接依据。

### L3：知识层

- 非遗项目、地区、人物、材料、工具、步骤、作品、时间和机构等实体。
- 实体之间的关系，以及从证据片段抽取的事实。
- 人工修订摘要、术语和步骤说明。

### L4：应用层

- 地图统计、详情页文案、3D 流程配置、推荐关系、常见问答和缓存结果。
- 所有内容保留对 L2 证据层的引用。

## 6. 视频处理流程

### 6.1 视频入库与盘点

1. 为视频分配 `video_id`，计算文件哈希。
2. 写入专题片、集数、地区、项目和授权元数据。
3. 检查文件能否播放、音轨是否存在、时长是否完整。
4. 生成统一的网页播放版本和低码率预览版本。
5. 建立处理状态：待处理、处理中、待审核、已发布、需返工。

### 6.2 音频与字幕处理

1. 从视频提取音频并做适度降噪、响度标准化。
2. 使用语音识别生成带时间码的初始字幕。
3. 使用上海非遗词表修正项目名、人名、地名和工艺术语。
4. 对访谈进行说话人分段。
5. 将原字幕、自动字幕和人工修订字幕分别保存，不相互覆盖。

建议建立自定义词表，至少包括：

- 首版 8 门非遗项目名称及别名，并为后续项目预留词表扩展机制。
- 上海各行政区、镇、村和历史地名。
- 传承人、机构和专题片中出现的人名。
- 材料、工具、技法和曲牌等专业词汇。

遇到沪语、方言或口述不清的内容，应降低置信度并进入人工复核队列，不依赖模型猜测。

### 6.3 镜头、关键帧与 OCR

1. 检测镜头切换，将视频划分为连续场景。
2. 从每个场景选择清晰且具有信息量的关键帧。
3. 对字幕条、标题卡、老照片说明和工具标签执行 OCR。
4. 识别关键画面类型：人物、材料、工具、手部动作、制作中间态、成品、地点。
5. 关键帧保留 `frame_time_ms`，可以跳回视频原位置。

视觉模型生成的描述只作为检索辅助，不能单独作为历史事实或工艺步骤的证据。

### 6.4 证据片段切分

证据片段不按固定字数机械切分，而应综合以下边界：

- 句子和段落结束。
- 说话人变化。
- 镜头或主题变化。
- 工艺步骤开始和结束。
- 材料、人物或历史事件的完整说明。

首轮参数建议：

- 单片段约 20—60 秒。
- 字幕约 200—500 个汉字。
- 相邻片段保留少量上下文重叠。
- 一个完整工艺步骤可以单独形成片段，即使长度不同。

每个片段生成稳定的 `segment_id`，任何后续摘要或事实都引用这一编号。

### 6.5 知识抽取

从证据片段中抽取以下内容：

- 实体：项目、地区、人物、机构、材料、工具、作品、技法、时间和地点。
- 关系：项目属于地区、人物传承项目、工具用于步骤、材料形成作品等。
- 事实：形成时期、工艺特征、用途、保护状态和历史变化。
- 工艺步骤：步骤序号、材料、工具、动作、结果、注意事项。
- 术语：名称、解释、别名和相关片段。

AI 可以生成候选结果，但关键事实进入正式知识库前必须审核。

## 7. 知识模型

### 7.1 核心实体

```text
非遗项目 Craft
├── 地区 District
├── 人物 Person
├── 机构 Organization
├── 材料 Material
├── 工具 Tool
├── 工艺步骤 ProcessStep
├── 作品 Artifact
├── 时间事件 Event
└── 证据 EvidenceSegment
```

### 7.2 工艺步骤模型

证据步骤层每一步至少包含：

- `step_id`：步骤唯一编号。
- `craft_id`：所属工艺。
- `order`：步骤顺序。
- `name`：步骤名称。
- `materials`：视频中识别出的候选材料。
- `tools`：视频中识别出的候选工具或物件。
- `action`：视频中的真实动作描述，保留原句。
- `result`：完成后的形态变化。
- `interaction_mapping`：网页中的拖拽、描画、组合等交互映射。
- `evidence_ids`：支持该步骤的视频证据。
- `review_status`：是否经过人工审核。

`materials` 和 `tools` 是证据抽取字段，不应直接作为工作台答案。交互层另设 `interaction_rules.json`，将工具转换为 `resource.kind = implement`，统一使用“一个或多个资源 + 标准动作 + 输出状态”的规则；资源组需明确 `all`、`any`、`range` 或 `optional`。详细结构见：[工艺工作台材料—动作规则与数据审核方案](./工艺工作台_材料动作规则与数据审核方案.md)。

### 7.3 证据记录模型

每条证据至少包含：

- `evidence_id`。
- `video_id` 和视频标题。
- `start_ms`、`end_ms`。
- 修订后的字幕原文。
- 说话人或旁白角色。
- 关键帧及其时间码。
- 数据集、提供机构和授权信息。
- 自动处理置信度。
- 人工审核人、审核时间和审核状态。
- 由该证据支持的事实、实体和步骤编号。

### 7.4 事实与证据的关系

一条事实可以有多个证据，一条证据也可以支持多个事实。

```text
事实
  → 支持证据 A：视频 1，02:14—02:36
  → 支持证据 B：视频 2，11:08—11:25
  → 状态：已核验 / 存在冲突 / 资料不足
```

如果多个视频出现冲突，不直接覆盖其中一个版本，应保留冲突记录并提交人工判断。

## 8. 存储与索引方案

首版建议减少基础设施数量，采用“对象存储 + 关系数据库 + 全文/向量索引”的组合。

| 组件 | 保存内容 | 建议 |
|---|---|---|
| 对象存储 | 原视频、播放视频、音频、关键帧、字幕文件 | 本地文件服务或兼容对象存储 |
| 关系数据库 | 项目、人物、步骤、来源、审核和关系 | PostgreSQL 等关系数据库 |
| 全文索引 | 字幕、名称、术语和精确关键词 | 数据库全文检索或独立搜索引擎 |
| 向量索引 | 证据片段和审核知识的语义向量 | 首版可使用 pgvector，减少独立服务 |
| 缓存 | 热门问题、项目摘要、会话上下文 | 内存缓存或 Redis |

不建议只使用向量数据库。项目名称、人物、年份和工艺术语需要精确检索，必须结合元数据筛选和全文检索。

## 9. 知识库索引策略

### 9.1 建立两类索引

**证据索引**：索引带时间码的字幕片段，用于回答引用和视频跳转。

**知识索引**：索引经过审核的事实、术语、项目简介和工艺步骤，用于快速、稳定地回答常见问题。

智能体优先检索知识索引，再获取对应证据片段；如果知识层没有答案，可以检索证据层，但应提高回答谨慎程度。

### 9.2 混合检索

推荐流程：

```text
用户问题
  → 判断当前项目、地区和步骤
  → 元数据过滤
  → 全文检索 + 向量检索
  → 合并去重
  → 轻量重排
  → 选取 3—5 条核心证据
  → 生成带引用回答
```

- 全文检索负责项目名、人名、地名、年份和专业术语。
- 向量检索负责用户口语表达和资料原文之间的语义匹配。
- 元数据过滤优先使用当前页面的项目、地区和步骤，缩小检索范围。
- 重排模型只处理初筛后的少量候选，减少延迟。

### 9.3 关系检索

地图和推荐功能可以直接读取结构化关系，例如：

- 同地区项目。
- 同类工艺。
- 使用相同材料或工具的项目。
- 同一人物或机构相关项目。

关系推荐应由数据库查询完成，不必每次调用大模型。

## 10. 智能体证据可溯源方案

### 10.1 回答原则

- 只使用本次检索到的证据回答事实性问题。
- 每个关键事实后绑定引用编号。
- 不确定、冲突或没有证据时明确说明。
- 区分视频原话、系统整理和智能体解释。
- 智能体不能以真实传承人的身份说话。

### 10.2 引用展示

每条引用建议显示：

- 专题片和集数。
- 视频时间段。
- 一句证据摘要或字幕原文。
- 关键帧缩略图。
- “查看片段”按钮。

用户点击后，播放器从 `start_ms` 前少量上下文开始播放，并在 `end_ms` 后停止或提示片段结束。

### 10.3 回答生成约束

送入生成模型的上下文应包含：

- 当前项目、地区、页面和工艺步骤。
- 用户问题。
- 经过重排的证据片段。
- 每个片段的稳定 `evidence_id`。
- 回答规则和拒答规则。

模型输出引用编号后，由服务端验证引用是否真实存在、是否属于本次检索结果。引用无效时不直接返回用户，应重新生成或降级为证据列表。

### 10.4 证据覆盖检查

回答返回前执行轻量检查：

- 人名、年份、地区和步骤是否有引用。
- 引用是否支持对应句子，而不只是主题相近。
- 回答是否引入证据中没有出现的新事实。
- 是否需要显示“资料不足”或“资料存在不同说法”。

## 11. 低延迟设计

### 11.1 核心原则

- ASR、OCR、关键帧提取、知识抽取和向量生成全部离线完成。
- 用户查询时只做过滤、检索、少量重排和回答生成。
- 优先利用当前页面上下文，避免检索全部视频。
- 常见问题和页面摘要提前生成并缓存。
- 回答使用流式输出，让用户尽早看到首段内容。

### 11.2 快慢两条回答路径

**快速路径**适用于：

- 当前项目简介。
- 当前步骤提示。
- 材料、工具和术语解释。
- 同地区、同类别项目推荐。

这些问题优先读取结构化数据库或已审核问答，必要时补充引用，不必进行大范围检索。

**深度路径**适用于：

- 跨项目比较。
- 历史演变和人物关系。
- 多个视频中的综合问题。
- 资料冲突分析。

深度路径可以增加检索和重排范围，并向用户显示“正在查找更多资料”。

### 11.3 初始延迟目标

以下为首版工程目标，需要根据部署环境实测调整：

| 阶段 | 目标耗时 |
|---|---:|
| 页面上下文与元数据过滤 | 50 ms 内 |
| 混合检索 | 300 ms 内 |
| 候选重排 | 300 ms 内 |
| 首个回答字符出现 | 2 秒左右，P95 不超过 3 秒 |
| 常规回答完成 | 3—6 秒 |
| 结构化步骤提示 | 500 ms 内 |

### 11.4 缓存与预取

- 缓存每个项目的简介、材料、工具、步骤和常见问题。
- 缓存时将“项目版本 + 知识库版本 + 问题规范化结果”作为键，知识更新后自动失效。
- 用户进入详情页时，预取该项目的高频证据和下一步工艺提示。
- 用户进入某一步骤时，预取相邻步骤，而不是加载整部视频。
- 视频引用片段使用分段流媒体或小范围预加载，避免点击引用后重新下载完整视频。

### 11.5 上下文控制

- 常规回答只传入 3—5 条核心证据。
- 优先传入短证据摘要，同时保留原字幕供引用检查。
- 历史会话只保留当前问题所需的信息，避免上下文持续膨胀。
- 地图页、地区页和详情页使用不同的查询范围。

## 12. 数据在网站中的充分使用

| 网站模块 | 使用的数据 |
|---|---|
| 上海地图 | 项目、地区、类别和数量统计 |
| 地区页 | 地域介绍、项目关系、代表片段和关键帧 |
| 非遗详情 | 审核摘要、历史事实、人物、材料、工具和作品 |
| 3D 热点 | 工具、部位、材料特性和证据片段 |
| 制作流程 | 结构化步骤、动作、结果和步骤证据 |
| 智能讲解 | 证据片段、审核知识、术语和关系 |
| 关联推荐 | 地区、类别、材料、工具和人物关系 |
| 小蕉动画 | 当前页面、当前步骤、检索状态和完成状态 |
| 数据说明页 | 数据来源、处理流程、授权、模型和版本 |

### 12.1 视频不只作为资料附件

视频应被拆解并用于多个界面：

- 地图悬停时展示地区代表性关键帧。
- 详情页用短片段支持历史和工艺说明。
- 3D 热点打开对应实拍动作。
- 智能体引用直接跳到相关时间码。
- 工艺步骤完成后对照真实影像中的成品状态。

## 13. 人工审核机制

### 13.1 审核优先级

**必须审核**：

- 项目名称、地区、级别。
- 人名、机构、年代。
- 材料、工具和步骤顺序。
- 3D 交互对应的真实动作。
- 智能体常见问题答案。

**抽样审核**：

- 普通字幕、镜头标签和非关键画面描述。
- 自动生成的关键词和相似项目候选。

### 13.2 审核状态

- `auto_generated`：自动生成，不能直接作为正式知识。
- `needs_review`：等待人工检查。
- `verified`：已核验，可用于回答和页面展示。
- `conflicted`：资料存在冲突。
- `rejected`：错误或不适合使用。

## 14. 版本、审计与更新

- 原始视频版本、处理流水线版本、知识库版本分别记录。
- 字幕修订、事实修改和步骤调整保留修改记录。
- 每次发布生成知识库版本号和变更说明。
- 智能体日志记录问题、检索证据、回答、引用和耗时。
- 日志不保存不必要的个人信息，并设置保留期限。
- 知识更新后重新生成受影响片段的向量，不必重建全部索引。

## 15. 质量评估

### 15.1 数据处理指标

- 关键字段正确率：项目、地区、人名、年份和步骤。
- 字幕准确率：重点关注专有名词和工艺术语。
- 时间码偏差：字幕、关键帧和引用片段是否对齐。
- 关键帧有效率：是否清晰展示目标信息。
- 工艺步骤审核完成率。

### 15.2 检索与智能体指标

- 检索召回率：正确证据能否进入前几名结果。
- 引用覆盖率：关键事实是否都有引用。
- 引用支持率：引用是否真正支持对应陈述。
- 无依据陈述率。
- 正确拒答率。
- 首字延迟、完整回答延迟和 P95 延迟。

首版可采用以下内部目标：

- 关键事实和工艺步骤 100% 人工审核。
- 事实性回答引用覆盖率不低于 95%。
- 常规问题首字 P95 不超过 3 秒。
- 结构化步骤提示 P95 不超过 1 秒。

这些是工程目标，不应作为未经测试的对外宣传数据。

## 16. 异常与降级方案

- 找不到证据：返回已有资料范围，并明确无法确认。
- 检索服务异常：读取已审核项目摘要和本地步骤数据。
- 生成模型超时：先返回证据列表和简短结构化答案。
- 视频无法播放：展示关键帧、字幕原文和时间码。
- 向量索引不可用：退回全文检索和元数据过滤。
- 页面网络较慢：先加载文字和缩略图，视频与 3D 延迟加载。

## 17. 实施阶段

### 阶段一：数据盘点与试点

- 盘点视频、授权和元数据。
- 选择 2—3 部代表视频试跑完整流程。
- 确定字幕、时间码、片段和审核标准。

### 阶段二：首批 8 门工艺加工

- 批量执行转写、OCR、镜头切分和关键帧提取。
- 建立项目、地区、人物、材料、工具和步骤实体。
- 完成重点事实和工艺步骤审核。

### 阶段三：知识库与检索

- 建立关系数据库、全文索引和向量索引。
- 完成混合检索、引用跳转和来源展示。
- 建立常见问答与项目摘要缓存。

### 阶段四：网站接入

- 接入地图统计、地区页和详情页。
- 将工艺步骤绑定 3D 状态。
- 接入智能体和小蕉动画状态。

### 阶段五：测试与扩展

- 测试引用准确性、拒答、延迟和降级。
- 修正高频错误和检索遗漏。
- 根据数据完整度先扩展至 12 门，再评估 16—20 门的范围。

## 18. 交付物

- 视频数据清单与授权台账。
- 原始视频、网页播放版和关键帧目录。
- 带时间码的自动字幕与人工修订字幕。
- 证据片段库和引用播放器。
- 非遗项目、人物、材料、工具和步骤数据库。
- 全文索引、向量索引和关系查询接口。
- 智能体检索、回答、引用和拒答接口。
- 数据处理脚本、模型版本和运行说明。
- 审核记录、质量报告和延迟测试报告。
- 面向评审的“数据与创作说明”。

## 19. 首要决策

开始开发前应优先确定：

1. 原始视频能否在本地或服务器完整访问，以及允许怎样展示片段。
2. 首批 8 门工艺分别对应哪些视频和集数。
3. 哪些视频包含方言、硬字幕或多人访谈。
4. 是否允许使用外部语音识别、视觉和生成模型处理数据。
5. 智能体最终部署环境、并发量和可接受成本。
6. 哪些工艺步骤可以由现有视频直接证明，哪些需要补充公开资料或人工校核。

## 20. 最重要的设计原则

> **知识库中的每条事实都应知道自己来自哪段视频；网站中的每个关键解释都应能回到这条证据。**

只要保持“原始视频—证据片段—审核知识—页面/智能体”这条链路，开放数据就能被充分使用，智能体也能同时兼顾可信度和响应速度。
