# 探物志 站内管理与协作手册

## 1. 这套管理方式如何工作

管理员和访客使用同一个网站、同一套路由与视觉界面。访客只能阅读；管理员登录后，可维护模块右上角会出现“编辑/保存”按钮，并可进入每个非遗项目的工序管理页。

```text
访客 → avonana.site → 浏览地图、项目与工作台
管理员 → avonana.site/#/admin/login → 同一网站的编辑模式
                                     ↓
                         /var/lib/sh-crafted/content.db
访客点击与投稿 → 社区接口 → /var/lib/sh-crafted/content.db
```

网站代码、知识库、证据和 3D 模型仍由 GitHub 管理。内容审核管理员调整的页面文字、工序和星图资料保存在服务器独立内容文件中，所以上传新版代码不会覆盖她已经保存的内容。

### 内容究竟放在哪里

项目现在使用一个 SQLite 正式数据库，JSON 仍作为导入、导出和迁移格式：

| 层级 | 本地位置 | 服务器位置 | 用途 |
| --- | --- | --- | --- |
| 当前生效的正式内容 | `.content/content.db` | `/var/lib/sh-crafted/content.db` | 网站实际读取；包含项目、工序、图片引用、星图和文字 |
| 社区统计与待审投稿 | 同一个 `content.db` | 同一个 `content.db` | 与正式内容共用数据库，但使用独立数据表和 revision |
| 迁移兼容文件 | `.content/content.json`、`.content/community.json` | 可保留旧 JSON | 首次迁移输入和人工备份，不再作为运行时主数据源 |
| 初始内容种子 | `scripts/content-seed.mjs`、`js/config.js`、`data/*/knowledge/process_steps.jsonl` | Git 仓库内相同路径 | 第一次创建内容库、补充新项目、保留原始抽取资料 |

`data/catalog.json` 只登记 8 个非遗数据包及其目录。每个项目原始工序位于对应数据包的 `knowledge/process_steps.jsonl`。这些 JSONL 是来源数据，不建议内容审核管理员直接覆盖；后台已发布的页面文字、工序和星图资料以 `content.db` 为准。

### 代码维护者与内容审核管理员的分工

1. 开发人员继续在 Git 分支修改 JavaScript、CSS、模型和初始数据。
2. 内容审核管理员通过线上管理入口直接修改文本、工序和知识星图，不修改 Git 仓库。
3. 内容审核管理员每次保存都会更新 `/var/lib/sh-crafted/content.db`；代码部署只更新 `/var/www/sh-crafted`，不会覆盖该文件。
4. 如果代码部署期间内容审核管理员仍打开旧页面，后保存者会收到版本冲突提示，需要刷新后基于最新版重改，避免静默覆盖。
5. 大批量审核前先运行 `deploy/backup-content.sh`。离线交换请使用管理后台导出的 JSON，不要直接替换线上数据库文件。

## 3. 直接编辑用户页面

登录后返回首页、地图或详情页。可编辑模块右上角会出现低透明度“编辑”按钮，鼠标移入后变清晰。

1. 点击“编辑”。
2. 直接修改页面中的文字。
3. 点击“保存”；不保留修改时点击“取消”。
4. 保存后页面刷新，访客与内容审核管理员会读取同一份新内容。

目前可直接编辑：

- 首页标题、介绍、资料来源按钮、统计说明和备案号。
- 行政区名称、区名由来、地区特色与非遗概览。
- 非遗项目名称、类别和项目简介。
- “成为第 n 位传承人”由服务器实时统计生成，不作为普通文本编辑，避免破坏序号显示。

纪录片证据、自动抽取的事实陈述和来源编号仍保持只读，避免展示编辑误改原始证据。

## 4. 社区投稿与审核

用户进入地图并点击某个行政区后，搜索栏旁会显示“添加文化遗产”。投稿分为两种：

- 简单便签：名称、类别和内容说明，不要求制作工序。
- 完整条目：可补充历史、特色、资料来源、封面与更多图片链接，并按需启用工序模块。

浏览器会在本机自动保存未提交草稿。正式提交后内容进入 `community.json` 的待审核列表，不会立即显示在地图中。管理员登录后进入“审核社区投稿”，可以查看投稿人联系方式、来源、图片及工序，并执行“审核通过并上线”或“驳回”。

审核通过时，系统会把投稿转换成现有的 `crafts`、`craft_steps` 和 `craft_gallery` 结构。新条目随后可以像已有项目一样在用户页面显示，并能继续使用原有工序管理页调整；没有工序的便签显示为阅读型条目。

项目查看次数按打开项目介绍或从列表进入项目累计。“第 n 位传承人”使用浏览器中的匿名访客 Cookie 去重：同一浏览器重复点击会保留原序号，清除浏览器数据或更换设备会被视为新访客。它只表达本站互动参与顺序，不代表官方认定的非遗代表性传承人。

完整的统计、投稿、审核、发布与重启持久化测试：

```bash
npm run community:test
```

## 5. 工序管理

进入“工序管理”，选择一个非遗项目：

- 横向签条代表工序，点击切换当前工序。
- 点击“新增工序”可增加工序。
- “前移/后移”调整工序顺序。
- 工序名称、工序说明和完成结果可直接输入。
- 材料和工具均可添加、删除、改名。
- 操作可以添加、删除、改名，并通过单选框指定当前工序的正确操作。
- 用户完成工序时，后台列出的材料和工具默认都属于必需项；仓库中已有的分组规则与“一键填入”预设会随保存保留。若修改材料或工具清单，系统会按新清单重新生成必需项，并清理失效的“一键填入”预设。
- 点击“保存全部工序”后，用户工作台立即使用新版规则。
- 每道工序可填写 `documentary_clips` JSON 数组。存在有效视频地址时，用户工作台会自动在桌面右侧展示纪录片窗口；没有片段时窗口不显示，也不占用桌面宽度。
- 页面最下方的知识星图编辑区可维护主节点和关联节点图片。图片字段使用 `title`、`image_url`、`description`、`source_url`，保存后由星图信息侧栏直接浏览。

如果内容审核管理员打开页面后，代码部署或其他浏览器页面先更新了内容，后保存的人会收到“内容已被其他页面或操作更新”的提示。此时刷新页面，基于最新内容重新修改，避免无提示覆盖。

## 6. 服务器配置

创建不随 Git 更新的内容目录：

```bash
sudo install -d -o ubuntu -g ubuntu -m 0750 /var/lib/sh-crafted
sudo install -m 600 /dev/null /etc/sh-crafted.env
sudo nano /etc/sh-crafted.env
```

写入：

```dotenv
DEEPSEEK_API_KEY=你的问答密钥
ADMIN_USERNAME=djt
ADMIN_PASSWORD=12345689
ADMIN_LOGIN_MAX_ATTEMPTS=50
CONTENT_DB_PATH=/var/lib/sh-crafted/content.db
# 首次迁移时保留；迁移完成后可移出环境文件
CONTENT_STORE_PATH=/var/lib/sh-crafted/content.json
COMMUNITY_STORE_PATH=/var/lib/sh-crafted/community.json
ADMIN_COOKIE_SECURE=true
```

首次启动且数据库不存在时，网站会把现有 `content.json`、`community.json` 导入 `content.db`；如果 JSON 不存在，才从仓库种子生成初始内容。迁移会自动保留带时间戳的 `.pre-db-时间.bak` 副本。数据库存在后，代码升级不会重新导入旧 JSON，也不会用种子覆盖管理员已经保存的内容。若数据库或迁移输入无效，服务拒绝启动，不会用默认数据覆盖线上编辑。

```bash
sudo systemctl restart sh-crafted
sudo systemctl status sh-crafted
curl http://127.0.0.1:7100/api/content
```

接口返回 `"source":"site-admin"` 表示站内内容系统工作正常。管理员使用 HttpOnly、SameSite 会话 Cookie；生产环境必须通过 HTTPS 访问。

## 7. GitHub 更新与在线内容

代码更新仍使用：

```bash
cd /var/www/sh-crafted
bash scripts/deploy.sh
```

部署脚本更新 `/var/www/sh-crafted` 并重启服务，不会删除 `/var/lib/sh-crafted/content.db`。服务重启后管理员需要重新登录，但已经保存的内容不会丢失。

如果仓库增加了全新的非遗项目，现有内容文件不会自动覆盖。应先备份内容，再由开发人员执行一次有针对性的数据迁移。

## 8. 备份

手动备份：

```bash
sudo bash /var/www/sh-crafted/deploy/backup-content.sh
```

脚本会备份 SQLite 数据库，并在存在时同时保留旧 JSON，备份保存在 `/var/backups/sh-crafted/`。建议每天备份，并把副本同步到服务器以外的位置。

定时任务示例：

```cron
20 3 * * * /bin/bash /var/www/sh-crafted/deploy/backup-content.sh >> /var/log/sh-crafted-content-backup.log 2>&1
```

恢复会覆盖线上编辑内容。恢复前先备份当前数据库，停止服务后把目标备份恢复为 `/var/lib/sh-crafted/content.db`，设置所有者为 `ubuntu:ubuntu`、权限为 `600`，最后重启 `sh-crafted`。
